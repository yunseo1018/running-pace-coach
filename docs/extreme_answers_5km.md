# 극단 정답 2개의 원자료 점검 (P2-3, 집계와 서술만)

생성: `scripts/52_extreme_answers_5km.py`. 대상은 cold-start test 평가 대상 352개 중 **정답 세션이 극단(T5 > 5,000초)인 2개**(민감도 S2에서 제거되는 행)다. personalized 평가에는 극단 정답이 1개 있다(`docs/sensitivity_results_5km.md`). 값·ID·좌표는 싣지 않았고 파생 길이·개수만 적었다. 결과 숫자·정의·모형은 바꾸지 않았다. 시각은 start_time 원값(기준 미확인)이다.

정의(실행 전 고정, 스크립트 docstring): 점 사이 구간의 속도 < 1km/h가 이어지는 구간을 정지 구간으로 보고(시간 합이 60초 이상인 묶음만 "정지 구간"으로 세고, 60초 미만 묶음까지 합한 값을 괄호에 병기), 점 간격 최대값은 연속 점 사이 시간의 최대다. 판정은 "명백한 오류"(거리 단위 이상이거나 메인 세션 표에서 같은 사용자의 다른 세션과 시간이 겹칠 때) 또는 "원인 미확인" 중 하나로만 한다. 긴 정지나 큰 점 간격은 휴식·일시정지·기록 중단일 수 있어 오류로 단정하지 않는다. **규칙 정정 이력**: 첫 실행에서는 스킵 구간(시간 역전·GPS 점프) 존재도 "거리 단위 이상"으로 세어 두 사례 모두 "명백한 오류"로 나왔다. 두 사례의 재계산 거리가 세션 표와 일치하고 점 사이 거리 최대가 작아(아래 표) 스킵 구간은 정상 기록에도 있을 수 있으므로 판정 기준에서 빼고 참고 값으로 옮겼다. 이는 결과를 본 뒤의 변경이다.

## 2. 판정과 해석

- 위 판정은 규칙 적용 결과일 뿐 원인을 단정하지 않는다. T5는 경과 시간 기준(정지·휴식 포함)이며 정지 구간이 길수록 T5가 커진다. 정지 구간이 "관측된 러닝 기록의 공백"인지 신호 대기·일시정지인지는 데이터에서 구분할 수 없다.
- **235.1초는 주 결과로 유지한다**(cold-start 사용자 평균 MAE, B2 235.117초, `docs/final_results_5km.md`). **205.1초(극단 정답 2개 제외 시 B2 205.102초)는 민감도 결과로만 쓰며** 235.1초를 대체하지 않는다(`docs/sensitivity_results_5km.md` S2).

## 3. 시연에서 이상 기록을 거르는 규칙 제안 (구현하지 않음)

- 원칙: **예측 시점에 관측 가능한 값, 곧 기준 기록 쪽 값만** 쓴다. 정답(미래) 값으로 거르지 않는다. 임계값은 train 안에서만 정하고(교차검증), test 결과는 "탐색 결과"로 표기한다.
- 이미 구현된 것: 기준 기록 T5 > 5,000초(극단)이면 유효 5km에서 제외한다(`demo/coach_demo.py`의 `is_valid_5km`).
- 제안(미구현): 기기에서 기준 기록 세션의 점 기록으로 (i) T5 구간 안 정지 구간 총 길이, (ii) T5 구간 안 점 간격 최대값을 계산해 입력 열로 받고, 둘 중 하나가 train 분포에서 정한 임계값을 넘으면 예측 대신 "기준 기록에 긴 정지나 기록 공백이 있어 예측이 불안정할 수 있음"이라고 경고한다(제외가 아니라 경고부터). 현재 입력 CSV에는 이 열이 없다.
- 위 규칙의 효과(예: 평가 대상 중 몇 %가 걸러지는지, MAE가 어떻게 달라지는지)는 계산하지 않았다.
