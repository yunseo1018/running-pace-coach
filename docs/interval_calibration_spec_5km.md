# 예측 범위 보정 사양 (결과 계산 전에 고정)

작성: 11월 1주차(P3). **이 문서를 만드는 시점에 보정한 범위의 test 포함률·폭·사용자별 분포는 계산하지 않았다.** 주 결론(49c02f8)·모델·정의·분할은 바꾸지 않는다. 바뀌는 것은 시연이 보여 주는 "명목 80% 범위"의 계산 규칙뿐이다(예측값 ŷ = a + b·x는 그대로).

- 분류: 범위 규칙은 **train 안에서만** 정한다(교차검증). test(cold-start test, personalized 평가)는 이미 열람한 자료이므로 아래 test 결과는 **"탐색 결과"**로 표기하며 "검증됐다"는 표현은 쓰지 않는다. test 결과를 보고 규칙을 바꾸지 않는다.
- 표기 규칙: "start_time 원값(기준 미확인)", "관측된 러닝 기록의 공백". 모든 평가는 "다음 7일 안에 적격 5km 기록이 관측된 경우"에 조건부다. 인과·처방 표현을 쓰지 않는다. ID·행 값은 출력·저장하지 않는다.
- 배경: 현재 시연 범위는 train 전체에 LAD를 한 번 적합한 뒤 **같은 자료의 잔차**(표본 내 잔차)의 10%·90% 분위수로 정했다(`demo/b2_params.json`, `docs/demo_interval_check.md`). 표본 내 잔차는 폴드 밖 예측 오차보다 작을 수 있어 범위가 좁게 나올 수 있다(cold-start test 포함률 73.9%, personalized 77.8%).

## 1. 범위 규칙 (보정)

1. 자료: train 평가 대상 1,720개·278명(`data/5km_dataset_train.pkl`, `docs/dataset_counts_5km.md`). test 사용자 자료는 쓰지 않는다.
2. 폴드: 사용자 단위 GroupKFold(5, seed 42) — `ridge_lib.group_kfold_indices(uid, 5, 42)`, `40_models_cv_5km.py`가 쓰는 것과 같은 분할.
3. 폴드마다 학습 폴드(4/5)에서 B2의 a_f·b_f를 LAD로 적합(`39_baselines.py`의 `lad_fit`)하고, **폴드 밖** 평가 대상의 잔차 r = y − (a_f + b_f·x)를 모은다. x = T5(기준) − m.
4. 모든 폴드 밖 잔차(1,720개)에서 q10_oof, q90_oof = 10%·90% 분위수(`np.percentile`, 선형 보간).
5. **보정 범위 규칙** = ŷ + [q10_oof, q90_oof]. ŷ = a + b·x는 시연의 B2(train 전체에 LAD를 한 번 적합한 a, b; `demo/b2_params.json`)로 그대로다. 범위 폭 q90_oof − q10_oof는 모든 예측에 같다.
6. **기존 범위(비교용)** = ŷ + [q10_ins, q90_ins]. q_ins는 train 전체 LAD 적합의 표본 내 잔차 10%·90% 분위수(현재 `demo/b2_params.json`의 값, 스크립트가 같은 값을 재계산해 assert로 확인).

**시연은 test 결과와 상관없이 보정 범위 규칙(위 5)의 범위를 쓴다.** 결과를 보고 규칙을 되돌리거나 바꾸지 않는다(바꿔야 하면 train 교차검증으로 규칙을 다시 정하고 test는 "탐색 결과"로만 표기).

## 2. 평가와 보고 항목 (test cold-start·personalized 각각, 기존·보정 범위 나란히)

- 평가 행: 49c02f8의 평가 행. cold-start test 352개·71명, personalized 442개·250명(test 사용자 78개 포함, train 사용자의 뒤쪽 기준 시점이 섞여 있어 학습 자료와 완전히 독립이 아님 — [주석 11/9: 442건 중 364건이 시연 a·b와 범위를 만든 train 1,720건에 포함되어 독립 평가가 아님. 사양 본문은 그대로 두며 결과 문서 `interval_calibration_5km.md`는 personalized 포함률을 주 결과로 싣지 않는다]). ŷ는 두 조건 모두 시연의 B2(cold-start train 적합 a, b)로 계산한다(`docs/demo_interval_check.md`와 같은 방식).
- 보고 항목:
  1. **포함률**(풀링) = 정답 y가 [ŷ+q10, ŷ+q90]에 들어간 평가 대상의 비율. 범위 아래/위로 벗어난 비율도 참고로 함께 적는다.
  2. **평균 폭(초)** = q90 − q10.
  3. **사용자별 포함률 분포**: 사용자별 포함률(그 사용자의 평가 대상 중 범위 안 비율)의 중앙값, 25%·75% 분위수(IQR), **포함률이 50% 미만인 사용자 비율**(분모 = 사용자 수).
  4. **풀링 포함률의 사용자 단위 bootstrap 95% CI**: 사용자를 복원추출 2,000회, seed 42, 백분위 CI. 두 범위와 두 조건에 같은 추출을 쓴다.
  5. 참고: train 폴드 밖 잔차 자체의 범위 안 비율(두 범위, 표본 내/폴드 밖). 보정 범위의 폴드 밖 포함률은 구성상 약 80%다.
- 폴드별 a_f·b_f의 범위(최소~최대)와 q10_oof·q90_oof를 함께 적는다.

## 3. 해석 규칙 (미리 고정)

- 포함률 CI가 명목 80%를 **포함하면** "명목 80%에서 벗어났다고 확정할 수 없음", CI **상한이 80%보다 작으면** "명목 80%보다 낮음", CI **하한이 80%보다 크면** "명목 80%보다 높음"이라고 쓴다. "검증됐다", "보장한다", "정확하다"는 쓰지 않는다.
- 폭이 넓어지는 만큼 포함률이 커지는 것은 구성상의 교환이며, 범위가 개별 예측의 정확성을 뜻하지 않는다. 개인에게 80%를 보장한다고 쓰지 않는다.
- 사용자별 포함률은 평가 대상이 1개뿐인 사용자에서 0% 또는 100%가 되므로 분포의 해석에 한계가 있다(평가 대상 수 분포를 함께 적는다).
- 이 결과로 주 결론, 모델, 정의, 분할, ŷ의 계산식을 바꾸지 않는다.

## 4. 시연 표시 (결과와 무관하게 미리 고정)

- "80% 범위" → **"명목 80% 범위"**.
- 그 아래 줄: "테스트 포함률 xx%(탐색 결과), 개인에게 80%를 보장하지 않음". xx = **보정 범위의 cold-start test 포함률**(2절 1, 소수 1자리; 시연의 a, b가 cold-start train 적합이므로).
- 한 줄 추가: "다음 7일 안에 5km 기록이 관측된 경우를 기준으로 한 예측입니다".
- 보정 문구: "직전 기록이 평소보다 N초 느렸던 만큼 다음 기록을 평소 쪽에 가깝게 예측했습니다(기록이 평소 주위에서 흔들리는 통계적 현상이며, 원인 효과가 아님)" (빠를 때는 "빨랐던 만큼"; 같을 때 문구는 기존 유지).
- 시연의 `demo/b2_params.json`은 `resid_q10`, `resid_q90`을 보정 값으로 바꾸고 기존 값은 `resid_q10_insample`, `resid_q90_insample`로 보존한다.

## 5. 해석 보완 (정의에 없는 부분의 가장 좁은 읽기)

1. 폴드의 학습 폴드에서 적합한 a_f·b_f는 폴드 밖 잔차에만 쓰고 시연의 a·b로 쓰지 않는다(시연의 a·b는 train 전체 적합 그대로).
2. 잔차 부호: r = y − ŷ (y = T5(정답) − T5(기준), 음수 = 개선).
3. 분위수의 선형 보간 방식은 `np.percentile` 기본값이다.
4. 사용자별 포함률의 IQR 분위수도 `np.percentile` 기본값을 쓴다.
