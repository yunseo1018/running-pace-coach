# 시연 "예측 저장(--log)과 결과 연결(--resolve)" 사양 (구현 전 고정)

대상: `demo/coach_demo.py`의 `--log`, `--resolve`/`--data`, 화면 상태 표시. B2 계산식·파라미터(`demo/b2_params.json`)·명목 80% 범위는 바꾸지 않는다. 이 문서는 구현 커밋보다 먼저 커밋한다.
교수 피드백(11/9) 4·5번의 "예측을 먼저 저장하고, 나중에 실제 결과와 연결한다"를 1인 사용 수준에서 확인 가능하게 만드는 것이 목적이다. 새 평가나 성능 주장은 하지 않는다.

> **1인 기록은 입력 연결·계산·표시 확인 사례이며 일반화 성능의 근거가 아님.** (`--resolve` 요약에 항상 출력한다.)

## 1. 예측 저장 `--log <파일>`

```
python demo/coach_demo.py <CSV> --asof <시점> --log <파일.jsonl>
```

- 평소 출력(예측 부분)은 `--log` 유무와 무관하게 같다. 저장하고 나면 끝에 한 줄 "예측을 저장했습니다(<N>번째 줄)."만 덧붙인다.
- 실행할 때마다 **한 줄(JSON Lines, UTF-8, 줄 끝 `\n`)**을 파일 끝에 추가한다. 파일이 없으면 만든다. 같은 (asof, 입력 CSV sha256, 코드 커밋)의 줄이 이미 있으면 추가하지 않고 "이미 저장되어 있습니다"라고 알린다(중복 방지).
- 저장 항목(키 이름 고정):

| 키 | 내용 |
|---|---|
| `logged_at` | 저장 시각(UTC ISO, 예: `2026-11-09T05:12:33Z`) |
| `asof` | `--asof` 원문 문자열 |
| `asof_epoch` | `--asof`를 에포크 초로 바꾼 값(시간대 표기가 없으면 UTC로 둠, 입력 파서와 같음) |
| `csv_sha256` | 입력 CSV 파일 바이트의 sha256 |
| `code_commit` | 실행 시점 `git rev-parse HEAD`(실패하면 `unknown`), `code_dirty` = `demo/` 안 미커밋 변경 유무(true/false) |
| `params_sha256`, `notes_sha256` | `demo/b2_params.json`, `demo/stratum_notes.json` 파일의 sha256 |
| `status` | `예측` 또는 `입력 부족` |
| `pred_sec`, `range_lo_sec`, `range_hi_sec` | 점예측과 명목 80% 범위(초, 화면의 mm:ss와 같은 반올림 정수). `입력 부족`이면 `null` |
| `notices` | 뜬 조건별 안내 종류의 목록: `과거 5km 1개` / `과거 5km 2~4개` / `평소와 2분 넘게 차이` / `정지 5분 초과` / `정지 정보 없음`(해당 없으면 빈 목록) |
| `kind` | `후향 점검`(입력 CSV에 시작 시각이 asof 이후인 세션이 이미 있음) 또는 `전향`(없음) |
| `n_later_sessions` | 입력 CSV 중 시작 시각이 asof 이후인 세션 수(개수만) |

- **저장하지 않는 것**: 좌표, 개별 기록 값(날짜별 거리·시간·T5·심박), CSV 행. 예측에는 쓰이지 않는다. 테스트가 저장된 줄에 이런 값이 없음을 확인한다.
- `--log`가 저장소 폴더 안을 가리키면 개인 기록이 커밋될 수 있으므로 멈추고 안내한다(가져오기 스크립트와 같은 규칙). `.gitignore`에 `*.mine.jsonl`을 추가한다.
- "후향 점검"은 결과가 이미 입력에 들어 있는 시점에서 코드가 돌아가는지 보는 점검이다. 예측 계산은 asof 이전에 끝난 기록만 쓰므로 값은 같지만, **전향 예측(결과를 모르는 상태에서 먼저 저장)과 구분해서 센다.**

## 2. 결과 연결 `--resolve <파일> --data <CSV>`

```
python demo/coach_demo.py --resolve <파일.jsonl> --data <CSV> [--detail]
```

저장된 줄마다, `--data` CSV에서 **[asof, asof+7일)에 시작한 5.0~5.5km이고 `t5_sec`가 있는 가장 이른 달리기**(극단 T5 > 5,000초도 제외하지 않음)를 찾는다. 기존 피드백 규칙(`docs/demo_feedback_spec.md` 3절)과 같은 함수를 쓴다. 상태는 아래 넷 중 하나다.

| 상태 | 조건 |
|---|---|
| **결과 관측** (범위 안 / 빠름 / 느림) | 적격 기록이 있음. 저장된 `range_lo_sec`·`range_hi_sec`와 `round(T5)`를 비교(피드백과 같은 반올림). 7일이 아직 지나지 않았어도 가장 이른 적격 기록이 정해졌으면 관측이다 |
| **결과 미관측** | `asof + 7일`이 현재 시각 이하이고 적격 기록이 없음 |
| **7일 미경과** | `asof + 7일`이 현재 시각보다 뒤이고 적격 기록이 아직 없음 |
| **입력 부족** | 저장된 줄의 `status`가 `입력 부족`(예측이 없음) |

- **결과 미관측은 실패나 적중으로 세지 않는다.** 범위 안 비율 같은 "적중률"을 계산하지 않는다. 관찰 기간(7일)을 늘리거나 7일 안에서 "가장 좋은 기록"을 고르지 않는다. 항상 가장 이른 적격 기록 하나만 쓴다.
- 비교 대상이 되는 5.0~5.5km 기록이 있으나 모두 `t5_sec`가 없으면 결과 미관측이며, 그런 줄의 개수만 요약에 덧붙인다.
- **공유 정답 세션**: 서로 다른 저장 줄(예: 하루 간격으로 저장한 예측 여러 개)의 [asof, asof+7일)가 겹쳐 같은 미래 세션(같은 시작 시각)을 정답으로 공유하면, 상세 표에 "공유"로 표시하고 요약에서 **독립 결과 수**(서로 다른 정답 세션의 수)를 따로 센다.
- 요약 항목: 전체 예측 수 / 입력 부족 / 결과 관측(범위 안·빠름·느림 개수, **독립 결과 수**) / 결과 미관측 / 7일 미경과. 합이 전체 예측 수와 같음을 코드가 확인한다. 전향·후향 점검별로도 같은 표를 나눠 보여 준다.
- 기본은 요약만 출력한다. `--detail`을 주면 줄마다 (번호, 종류, asof 날짜, 상태, 공유 표시)를 보여 준다(점예측 값은 나열하지 않는다).
- `--data` CSV의 sha256과 저장 줄의 `csv_sha256`가 다를 수 있다(기록이 늘어난 같은 파일). 요약에 `--data`의 sha256을 적는다. 연결에는 저장된 예측만 쓰고 예측을 다시 계산하지 않는다.
- 줄 형식이 틀리면 멈추지 않고 "오류: N번째 줄을 읽을 수 없습니다 / 해결: ..." 두 줄과 종료 코드 2로 알린다.

## 3. 화면 상태 표시 (구현 커밋에 포함)

1. 결과 첫 줄 바로 아래에 두 줄을 둔다.
   - `다음 7일 안 적격 5km 기록이 관측되는 경우에 대한 예측입니다(명목 80% 범위)`
   - `실측 포함률 75.3%(cold-start test, 탐색 결과), 개인에게 80%를 보장하지 않음` — 숫자는 `test_coverage_cold`뿐이다(personalized 포함률은 학습 자료와 겹쳐 독립 평가가 아니므로 쓰지 않는다).
   - 이전의 "테스트 포함률 …" 줄과 "다음 7일 안에 5km 기록이 관측된 경우를 기준으로 한 예측입니다" 줄을 이 두 줄로 바꾼다(순서: 예측 줄 → 관측 조건 줄 → 포함률 줄).
2. 상태 표시를 셋으로 구분한다.
   - `[입력 부족]`: 자격 미달로 예측이 없을 때 "예측할 수 없습니다" 앞에 붙인다(피드백 블록에서는 "예측이 없어 비교하지 않습니다" 앞).
   - `[조건별 검증 부족: 개발 결과 기준 경고]`: 조건별 안내 줄이 하나라도 있을 때 안내 줄들 바로 앞에 한 줄로 붙이고, 그 줄에 "train 폴드 밖 개발 결과 기준이며 새 자료로 확인되지 않았습니다"를 덧붙인다. (정지 정보 없음 안내만 있을 때는 붙이지 않는다.)
   - `[결과 미관측]`: 피드백 블록에서 7일이 지났는데 적격 기록이 없을 때 "다음 7일 안에 비교할 5km 기록이 없습니다" 앞에 붙인다. 7일이 아직 지나지 않았으면 붙이지 않는다(그 경우는 "아직 7일이 지나지 않았습니다"다).
3. `--feedback`·`--log` 없이 실행했을 때 기존과 달라지는 부분은 위 1·2뿐이다. 테스트, 합성 예시 출력(`demo/examples/*.out.txt`), README, 사례표(`docs/demo_cases.md`)를 함께 갱신한다. 예측값·범위·계산식은 바뀌지 않는다는 점을 테스트로 고정한다.

## 4. 금지 표현

피드백 블록과 같은 목록(`docs/demo_feedback_spec.md` 7절)을 `--resolve` 출력과 새로 추가한 상태 문구에도 적용한다: 훈련·휴식 권고, 실력 변화 판정, 목표 달성 확률, 원인 설명. 요약에 "성능", "적중률", "정확도" 수치를 쓰지 않는다.

## 5. 테스트(합성 데이터)

상태 4종(결과 관측 3가지 위치 포함) / 공유 정답 세션과 독립 결과 수 / 7일 경계(정확히 asof+7일 시작은 제외, 정확히 7일이 지난 시각) / 해시 기록(csv·params·notes sha256과 코드 커밋 키) / 좌표·개별 기록 값 미저장 / 금지 표현 없음 / 중복 줄 방지 / 저장소 안 경로 거부 / 전향·후향 구분 / 합계 일치 / `--log`·`--feedback` 없는 출력이 화면 상태 표시 변경분을 뺀 나머지에서 같음. 기존 테스트는 전부 통과해야 한다(기대 문구가 바뀐 곳은 이 사양대로 갱신).

## 6. 내 기록 동작 확인(저장소 밖, 커밋하지 않음)

예측 가능한 과거 월요일 21개 시점(후향 점검)과 오늘(2026-11-09) 시점을 `--log`로 `my_runs/predictions.mine.jsonl`에 저장하고 `--resolve`로 요약한다. 개별 날짜·기록 값은 보고하지 않는다.

## 7. 변경하지 않는 것

B2 식과 파라미터, 명목 80% 범위(폭과 위치), 조건별 안내의 층과 수치, 피드백 규칙과 분위수 표, 연구 문서의 결론(49c02f8 범위).
