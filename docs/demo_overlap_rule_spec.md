# 시연의 시간 겹침 기록 처리 (연구 파이프라인과 맞춤)

B2 계산식·파라미터·범위·안내 규칙은 바꾸지 않는다. 입력 기록을 세는 방식만 연구 데이터의 중복 제거 단계와 맞춘다.

## 연구 파이프라인이 한 일 (코드 인용)
- 중복 판정(`16_duplicate_dedup.py` 72–73, 129–156): 같은 사용자 안에서 ① 시작 시각 차이 ≤ 60초(`NEAR_SIMULTANEOUS_START_SEC = 60`), ② 시작 좌표 거리 ≤ 50m(`NEAR_SAME_LOCATION_M = 50`), ③ 시간 구간 겹침(`max(start) < min(end)`, 151행)을 모두 만족하는 쌍은 같은 운동의 중복 기록으로 보고 한쪽만 남긴다.
- 남기는 쪽(`16_duplicate_dedup.py` 205–216): GPS 점 개수 많은 쪽 → duration_sec 긴 쪽 → session_id 작은 쪽.
- 병합(`17_dedup_merge_rebuild.py` 57–59, 75–76): 앞 기록 종료와 다음 기록 시작의 간격이 0~180초이고 거리·속도 조건을 만족하는 조각만 잇는다. **간격이 음수(시간이 겹침)인 쌍은 병합 대상이 아니다**(그래서 겹침은 중복 제거 단계에서만 처리된다). 순서는 중복 제거 → 병합.

## 시연에 적용하는 규칙
- 대상: `load_sessions`가 읽은 기록(기존의 "시작·종료 시각이 같은 중복" 제거 뒤). 시작 시각 차이 ≤ 60초이고 시간 구간이 겹치면 한 묶음으로 보고 1건으로 센다.
- 남기는 기록: 경로가 있는 기록(`stop_sec`가 있는 기록; 연구의 "GPS 점 개수 많은 쪽"에 해당) → 더 긴 기록 → 먼저 시작한 기록.
- 맞추지 못하는 부분: 시작 좌표 50m 조건은 시연 CSV에 좌표가 없어 적용할 수 없다(좌표는 저장하지 않는다). 그래서 시각 조건만으로 판정한다. 연구 쪽보다 넓게 묶일 수 있다.
- 병합(0~180초 간격 조각 잇기)은 시연에 넣지 않는다(좌표가 필요하고, 이번 범위가 아니다). 겹치지 않고 이어진 기록은 별개 기록으로 남는다.
- 표시: 처리했으면 `시간이 겹치는 기록 N건을 G건으로 처리했습니다(…)`를 안내(요약 화면 `[안내]`, 자세히 보기의 `※`)에 한 줄 넣는다. 없으면 표시 없음.
- 테스트: 시작 10초 차이로 겹치는 두 기록(하나는 경로 있음)→경로 있는 쪽 1건, 경로 없는 쪽이 더 길어도 경로 있는 쪽, 60초 초과는 별개, 겹치지 않는 연속 기록은 변화 없음.
