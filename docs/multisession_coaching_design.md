# 다중 세션 집계 코칭 평가 — 설계 문서 (10월 3주차 7번)

> **이 문서는 설계와 가용성 점검(표본 수를 세는 기술통계)까지만이다. 모델 학습·평가·구현은 하지 않았고, 구현은 사용자 승인 후에 시작한다.** 모든 목표는 합성 시나리오이며 실제 사용자 목표 기반 코칭 성능이 아니다. 설계안은 가용성 점검 결과를 보기 전에 `docs/week3_predeclaration.md` 10절에 먼저 기록했고 결과를 본 뒤 바꾸지 않았다. 사용자 ID·세션 ID·개인 경로는 쓰지 않는다. 가용성 표(5절)는 `python 34_multisession_availability.py`로 생성한다.

## 1. 두 과제와 주 과제 제안

| | (A) 현재 상태 판정 | (B) 다음 주 성과 예측 |
|---|---|---|
| 정의 | 최근 k주 집계 페이스로 현재 위치를 목표 대비 범주로 판정 | 예측 시점 t 이전에 끝난 세션의 집계로, t 이후 7일(타깃 주)의 집계 페이스를 예측 |
| 정답(ground truth) | **없음** | 있음: 타깃 주에 실제로 기록된 세션의 집계 페이스 |
| 판정/예측의 성격 | 판정이 관측된 집계값의 **결정적 함수**(같은 집계값이면 항상 같은 범주) → 맞고 틀림을 정의할 수 없음 | 예측값과 실제값을 같은 단위로 비교 가능, 같은 단위 baseline과 직접 비교 |
| 용도 | 코칭 문구가 어떤 값에 근거했는지 **설명** | 평가 가능한 **주 과제** |

**제안: (B)를 주 과제, (A)를 설명용 보조**(사용자 판단과 같은 의견이다). 근거:
1. (A)는 "현재 집계 페이스가 체크포인트보다 느린가"만 말하며 관측값이 정하므로 오류를 측정할 기준이 없다. 평가하면 판정 규칙의 정의를 확인하는 것에 그친다.
2. (B)는 실제 값이 있어 baseline과 같은 단위로 비교할 수 있다.
3. **(B)의 한계(단서)**: 평가 표본이 '타깃 주에 러닝이 있었던 앵커'로 조건부이다. 미래 활동 여부로 표본이 선택되므로 실제 서비스에서 '다음 주에 달릴지'는 예측하지 않는다. 이 선택의 크기를 가늠하려고 입력 조건은 만족하지만 타깃 주에 러닝이 없는 앵커 비율을 5절에 함께 기록한다. 이 점은 결과 해석 시 반드시 병기한다.

## 2. 고정할 항목 (값과 근거; 가용성 결과를 본 뒤 바꾸지 않음)

| 항목 | 고정 값 / 후보 | 근거 |
|---|---|---|
| 분석 단위 | (사용자, 앵커 주) | 같은 사용자도 주마다 다른 시점의 예측이 된다 |
| 앵커 시점 t | epoch 초를 **UTC로 해석한 월요일 00:00**의 7일 격자 | 데이터에 타임존 정보가 없음(미확인). 사용자 현지 시각으로 변환하지 않는다. 현지 요일 경계와 최대 ±14시간 어긋날 수 있다(한계). 격자 시작 요일을 바꿨을 때 표본 수가 얼마나 변하는지만 5절에서 기술통계로 확인 |

| 최소 입력 세션 수 | 후보 **3, 4** | 중앙값이 단일 세션 노이즈를 어느 정도 흡수하려면 최소 3개 이상 |
| 타깃 주 | 시작 시각이 `[t, t+7일)`인 세션 | t 이후 7일 |
| 타깃 주 최소 세션 수 | 후보 **1, 2** | 1이면 타깃이 단일 세션(기존 과제와 같은 단위), 2이면 두 세션의 중앙값(평균) |
| 페이스 집계 방식 | 세션별 경과 시간 기준 평균 페이스의 **중앙값** | 메인 정의와 동일, 극단 페이스(>1000초/km, 826건)에 강건. 거리 가중 페이스는 쓰지 않음(휴식 포함 세션의 영향이 거리 가중에서 더 커질 수 있어 단순 중앙값 채택) |
| 목표 기준 | 합성 목표 δ∈{3%,5%,10%}, 현재 능력=입력 집계 중앙값, 데드라인 8주, 주간 체크포인트=현재 능력에서 목표까지 선형 보간(`coaching_lib` 규칙 재사용). 타깃 주는 앵커 기준 1주차 | 3주차 4번과 동일한 합성 설정 재사용 |

### 2-1. 누수 규칙과 assert 방식
- **예측 시점에 끝나지 않은 세션은 입력에 넣지 않는다**: 입력 세션은 `end_time < t`만. t 시점에 진행 중이던 세션(`start_time < t ≤ end_time`)은 입력에도 타깃에도 넣지 않는다(타깃은 `start_time ≥ t`만).
- 전체 이력 baseline도 `end_time < t`인 세션만 사용한다.
- assert(구현 단계에서 앵커마다): `last_input_session_time := max(입력 세션 end_time) < t`, `min(타깃 세션 start_time) ≥ t`, 입력 세션 수 ≥ 최소 입력 세션 수, 타깃 세션 수 ≥ 최소 타깃 세션 수, 전체 이력 baseline에 쓰인 세션의 `end_time`이 모두 `< t`. 위반하면 중단한다. 가용성 점검 스크립트도 모든 앵커에 대해 앞의 두 조건을 assert로 검증한다.
- 정규화·하이퍼파라미터 선택 등 통계가 필요한 단계는 기존 규칙(허용된 학습 자료로만 fit, 테스트 점수로 선택 금지)을 따른다.

## 3. baseline, 지표, 통계 (같은 단위)
- **baseline**(앵커의 타깃 주 집계 페이스를 예측): (1) 직전 28일 입력 집계 중앙값, (2) `end_time < t`인 전체 이력 중앙값, (3) 마지막 세션 페이스(`end_time < t`인 가장 최근 세션). **집계했다고 오차가 자동으로 줄어든다고 가정하지 않는다.** 집계 기간·단위가 달라 기존 단일 세션 과제의 MAE와 숫자를 직접 비교하지 않는다.
- **지표**: MAE와 RMSE를 **둘 다** 보고하고 결론도 따로 쓴다. macro MAE(사용자별 평균)를 병기한다.
- **신뢰구간**: **사용자 단위 cluster bootstrap(2000회, seed 42)**, 모든 방법에 같은 추출을 적용한 쌍체 차이 CI. **사용자 단위 재표집을 쓰는 이유**: 같은 사용자의 앵커들은 28일 입력 창이 3주 겹치고 같은 이력을 공유하며 사용자 고유의 페이스 수준을 공유하므로 (사용자, 앵커) 표본이 서로 독립이 아니다. 앵커 단위로 재표집하면 유효 표본 수를 과대평가해 CI가 지나치게 좁아진다.
- 유의하지 않은 비교는 "동등성의 입증이 아님"으로 쓴다. 평가 조건은 기존과 같이 cold-start(사용자 단위 분할)와 personalized(사용자별 앵커 시간순 앞 80%/뒤 20%)로 나눈다.

## 4. 데이터와 단위에 대한 주의
- 입력은 정제 세션 데이터(중복 제거→병합) 기준이며, 극단 페이스 세션(>1000초/km)은 중앙값 집계에서 영향이 작지만 제외하지 않는다. 극단 세션 제외 민감도는 구현 단계에서 사전 선언 후 수행한다(3주차 5번의 사례 참고).
- 데이터의 시간 기록이 타임존·기기 시계 오류 면에서 정확한지는 점검하지 않았다(미확인). 세션 시작 시각의 범위는 2006~2016년으로 나타나며, 이상값 처리 규칙은 구현 단계에서 사전 선언한다.

## 6. 코칭 판정과의 연결 (개요, 한 문단)
주 과제 (B)의 예측 집계 페이스를 3주차 4번의 판정 범주(앞서감 ≤−3%, 계획대로 −3~+3%, 조금 뒤처짐 +3~+10%, 크게 뒤처짐 >+10%)에 같은 규칙으로 대입해 **주간 코칭 범주**를 만들고, 실제 타깃 주 집계 페이스로 만든 범주와의 불일치율을 보는 구조가 자연스럽다. 판정 보류는 별도 검증 자료의 out-of-sample 잔차 분위수로 만든 구간의 하·상한이 같은 범주일 때만 판정하는 3주차 4번 방식을 그대로 쓸 수 있다. 다만 **3주차 4번에서 단일 세션 예측의 구간 폭(103~195초/km)이 범주 폭(20~23초/km)보다 훨씬 넓어 보류율이 96~99%였다**. 주 단위 집계 타깃은 잔차의 규모가 작아질 수 있으나(집계의 분산 감소) 얼마나 작아지는지는 평가하기 전에는 알 수 없고(미확인), 작아져도 구간 폭이 범주 폭보다 넓으면 같은 문제가 반복된다. 따라서 보류 방식은 집계 타깃의 오차 규모를 측정한 뒤에 쓸지 결정한다. 또한 현재 능력을 입력 집계 중앙값으로 정의하면 '직전 집계 기간 중앙값' baseline의 판정이 구조적으로 한 범주에 몰리는 3주차 4번의 구조 효과가 반복되므로, 현재 능력 정의를 다르게 할지(예: 전체 이력 중앙값)는 구현 단계에서 결과를 보기 전에 사전 선언한다.
