## 2. 거리 차이 해결 확인과 타깃·첫 적격 세션 정의

### 2-1. 거리 차이 해결 확인

"거리 차이"를 두 가지 의미로 확인했다.

| 확인 항목 | 결과 | 출처 |
|---|---|---|
| 원본 점 기록에서 같은 규칙(`01_parse_run_sessions.py:total_distance_km`)으로 다시 계산한 총 거리와 세션 표 거리의 차이 | 점검 대상 원본 기록 10,460개, 다시 계산한 기록 10,460개, **1e-9km를 넘게 다른 기록 0개** | `docs/week5_target_check.md` 15행(A-1) |
| 재현 점검: 새 폴더에서 처음부터 다시 만든 `week5_target_check.md`가 원본 커밋본과 같은지 | 같음(이번 실행이 다시 쓴 21개 문서 중 `week5_target_check.md`를 포함한 20개가 동일, 다른 1개는 `environment.md`의 예측값 절) | `docs/repro_check_5km.md` 5절 |
| 서로 다른 길이의 세션 시간을 그대로 빼서 생기던 "거리 차이"(4.5~5.5km 완주 시간의 차이) | 기준 기록과 정답 세션 모두 **정확히 5.000km 지점까지의 시간 T5**로 바꿔 같은 거리를 비교(5.0km 미만 세션은 후보에서 제외, 5km 환산 시간은 민감도 S1로만) | 아래 2-2 정의, `docs/predeclaration_5km_final.md` |

한계: 작업 중 이 점검에서 한 번 불일치가 많이 나왔다가 속도 상한 상수(`25 / 3.6`)를 잘못 읽은 점검 스크립트의 오류를 고쳐 0건이 됐다. 이 이력은 저장소 문서에는 기록돼 있지 않다(작업 기록 기준). T5는 점 사이 선형 보간이라 점 간격이 긴 구간에서는 도달 시각이 덜 정밀하다(`week5_target_check.md` A-3).

### 2-2. 타깃·첫 적격 세션 정의 문장 (사전 선언 문서에서 그대로 인용)

출처: `docs/predeclaration_5km_final.md`

- 10행: 4. **5km 후보 세션**: `merged_count == 1` 이고 `actual_distance_km ∈ [5.0, 5.5]`(양 끝 포함). 병합 세션은 5km 후보에서 제외하되, 달리기 횟수와 입력값 계산에는 포함한다.
- 11행: 5. **5km 시간 T5**: 후보 세션의 점 단위 기록에서 `01_parse_run_sessions.py`와 같은 규칙으로 누적 거리를 만들고(시간차 0 이하·속도 초과 구간은 0 누적), 5.000km에 처음 도달하는 시각을 인접 두 점 사이 선형 보간으로 구한 뒤 (그 시각 − 세션 첫 timestamp)를 초로 쓴다. 정지 시간 포함(경과 시간 기준).
- 12행: 6. **극단 후보**: T5 > 5,000초(1km당 1,000초 초과).
- 13행: 7. **과거 자격**: 종료 시각 ∈ [t−28일, t)인 달리기 세션 4회 이상(병합 세션 포함, 길이 무관), 그리고 같은 창 안에 극단이 아닌 5km 후보 1개 이상. **기준 기록** = 그 창 안 극단이 아닌 5km 후보 중 시작 시각이 가장 늦은 것.
- 14행: 8. **미래 관측**: 시작 시각 ∈ [t, t+7일)인 5km 후보 1개 이상(극단 포함). **정답 세션** = 그중 시작 시각이 가장 이른 것.
- 15행: 9. **정답 y** = T5(정답 세션) − T5(기준 기록), 초. 음수 = 개선.

정답 세션은 "시작 시각이 가장 이른 것"(첫 번째 적격 5km 세션)이고, 기준 기록은 "시작 시각이 가장 늦은 것"(직전 5km)이다.
