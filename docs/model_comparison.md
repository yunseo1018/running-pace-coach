# 전체 종합 + LSTM 시도 여부 판단 (10월 2주차 9단계)

입력 메인 데이터: `data\run_sessions_deduped_merged.pkl` (세션 105709건, 사용자 854명, assert 통과)

모든 하이퍼파라미터는 6~8단계에서 이미 선택된 값을 그대로 재사용했다(재탐색 없음). 이 문서의 목적은 '같은 평가 윈도우에서 나란히 비교'다.

## 0. 입력 및 윈도우 수(6단계 대비 차이는 7단계 `docs/tree_results.md` 1-1절 참고)
- cold-start: train 79669건 / test 21977건
- personalized: history 81018건 / hold-out 20628건
- 5~6단계 원표는 04/06단계 윈도우(과거 정보 감사만 적용)를 썼고, 이 표는 7~8단계와 같은 24단계 확장 피처 윈도우(이력 감사 추가 적용)를 쓴다 — cold-start는 train 2건/test 1건, personalized는 history 2건/holdout 1건(경계 이동 포함 3건) 적다. **baseline/Ridge 숫자도 이 윈도우에서 다시 계산했으므로 5~6단계 표의 숫자와 약간 다르다(소수점 셋째 자리 수준) — 모델 차이가 아니라 평가 대상 윈도우 차이다.**

## 0-2. 사후 추가 baseline 4종 (ablation 결과를 본 뒤 추가 — 아래 4개로 고정, 더 추가하지 않음)
(a) 사용자 전체 이력 중앙값 (b) median-10 (c) median-20 (d) 0.5×median5+0.5×전체이력중앙값. 모두 타깃 시작 시각 이전 세션만 사용한다 — (a)/(d)의 전체이력중앙값 부분은 24단계가 이미 '이력 감사'(가장 늦게 참조한 세션 종료 시각 < 타깃 시작 시각)를 통과시킨 `user_history_median_pace` 피처를 그대로 재사용했고, (b)/(c)는 session_order가 0부터 시작하는 조밀한 시간순 인덱스라는 점(02/17단계에서 이미 확인)을 이용해 `session_order < target_session_order`인 세션만 썼다(새로운 리크 경로 없음).
- **median-10 이력 부족(10개 미만) 윈도우 비율**: cold-start 3.3% (715/21977), personalized 0.3% (67/20628) — 모자라면 있는 만큼만 중앙값을 계산했다(규칙).
- **median-20 이력 부족(20개 미만) 윈도우 비율**: cold-start 9.1% (1995/21977), personalized 1.1% (218/20628)

## 헤드라인 (확인된 사실 / 추정 구분)
**확인된 사실 (이 문서의 표와 CI에서 직접 읽힌 것)**
- 학습 모델(GBM, MLP)은 두 평가 조건 모두에서 median-5보다 MAE가 낮고 쌍체 차이 CI가 0을 포함하지 않는다(개선폭 2.6~3.0초/km, 4~5%) (윈도우 풀링 MAE 기준, 22피처 기준; 사용자별 MAE 평균(macro)에서는 일부 조건에서 CI가 0을 포함하고, cold-start GBM22처럼 점추정이 오히려 높은 경우가 있음 — `docs/same_scope_comparison.md` 7-3절). 그러나 이것만으로 끝나는 결론이 아니다:
- **사후 추가 baseline (median-10, median-20, 전체 이력 중앙값, 결합 규칙 (d))은 ablation 결과를 본 뒤 추가한 것이고, 후보 4개 중 가장 좋은 것(d)을 함께 보고하는 것이라 약간의 낙관(선택 편향) 가능성이 있다.** 이 4개는 고정했고 더 추가하지 않았다.
- **cold-start**: (d) 0.5×median-5+0.5×전체 이력 중앙값과 GBM/MLP의 MAE 차이: GBM−(d) +0.198 [-0.641, +1.266] (CI가 0을 포함해 구분되지 않음), MLP−(d) -0.106 [-0.543, +0.337] (CI가 0을 포함해 구분되지 않음) (초/km, 양수면 (d)가 더 낮음).
- **personalized**: GBM−(d) -0.668 [-1.374, +0.036] (CI가 0을 포함), MLP−(d) -0.780 [-1.403, -0.347] (CI가 0을 포함하지 않음) — 음수는 모델이 (d)보다 낮다는 뜻이며 점추정으로는 모델이 약 0.7~0.8초/km 낮고, 유의성은 CI 기준으로만 말할 수 있다.
- **코칭 판정(합성 시나리오, `docs/coaching_results.md`)**: 결과는 해당 문서의 요약 절 참고(예측기별 불일치율 차이와 CI는 거기서 계산).
- MAE와 RMSE의 순위는 다르다(3절). 개선폭 비율은 점추정 기준이며 2-3절에 계산 방식을 명시했다.

**추정/미확인**: (d)가 GBM/MLP만큼 좋은 이유(장기 페이스 수준 정보가 개선의 상당 부분을 설명한다는 가설)는 직접 검증하지 않았다. personalized에서 GBM/MLP가 (d)보다 낮은 이유(시간 순서 정보 활용 등)도 미확인이다.

## 분할기 변경에 따른 민감도 (MLP cold-start)
MLP의 cold-start 하이퍼파라미터 선택은 train 사용자 GroupKFold의 첫 fold를 검증으로 쓴다. 처음에는 sklearn GroupKFold(커밋 00c27d1 시점), 재현성 고정 후에는 ridge_lib GroupKFold로 바꿨고, **둘 다 유효한 CV 선택이다(어느 쪽이 더 낫다고 판단하지 않는다).** fold 구성이 바뀌자 선택된 구조가 달라져(2×64, wd=0, 97에폭 → 2×32, wd=1e-4, 112에폭) cold-start MLP 결과가 약 0.2초/km 움직였다:

| 분할기 | cold-start MLP test MAE | median-5 대비 개선폭(bootstrap 평균) |
|---|---|---|
| sklearn GroupKFold (이전 문서 기록값) | 59.578 | 2.661 |
| ridge_lib GroupKFold (현재) | 59.374 | 2.861 |

personalized(시간순 분할)와 GBM·Ridge·baseline은 분할기와 무관하게 불변. 자세한 비교는 `docs/mlp_results.md` 6절. 변동 원인(검증 fold 데이터 차이 vs 조기종료·에폭 변화)은 분해하지 않았다 — 추정/미확인.

## 2-4. Ridge 표기: 15피처 vs 22피처, 6단계 숫자와의 차이
- 종합표의 **6a는 15피처(과거 5세션x3, 24단계 윈도우)**, **6b는 22피처(+이력요약 7개, 7단계 확장)** 이다. 둘 다 표준화+Ridge(alpha=1e4), `ridge_lib.RidgePipeline`(numpy), 학습 구간 fit.
- **레거시 6a(Ridge15, alpha=1e4 재사용)와 `docs/same_scope_comparison.md`의 Ridge15(자체 CV alpha=1e-4, 6단계 원본과 일치)는 서로 다른 값이다.**
- cold-start: 15피처 MAE=70.274/RMSE=262.419, 22피처 MAE=65.681/RMSE=261.101
- personalized: 15피처 MAE=62.270/RMSE=239.443, 22피처 MAE=58.313/RMSE=241.292
- 6단계 문서(`docs/ridge_results.md`)의 Ridge 메인 숫자: cold-start MAE 69.928(RMSE 262.069), personalized MAE 62.054(RMSE 239.762). 같은 24단계 윈도우에서 15피처만 쓴 6a를 6단계 숫자와 비교하면:
- cold-start: 6a(15피처) MAE 70.274 vs 6단계 69.928 (차이 +0.346); 6b(22피처) 65.681 (6단계 대비 -4.247)
- personalized: 6a(15피처) MAE 62.270 vs 6단계 62.054 (차이 +0.216); 6b(22피처) 58.313 (6단계 대비 -3.741)
- **정정 및 원인 분해** (`docs/ridge_discrepancy.md`, 30_ridge_discrepancy.py): 이전 버전은 이 차이를 '피처 구성 때문'이라고 적었으나 틀렸다. 6a는 6단계와 같은 15피처다. 6단계 설정(ridge_lib, 04/06 윈도우, alpha=0.0001)은 MAE 69.928493 / 62.053868을 그대로 재현했고(S0), 윈도우를 24단계로 바꿔도 +0.001~0.002에 그쳤으며(S1~S3), **차이(+0.34 / +0.21)는 거의 전부 alpha 때문이다**: 종합표 6a는 7단계에서 22피처로 선택된 alpha=10000을 15피처에도 그대로 썼다(S4: ridge_lib로 alpha만 1e4로 바꾸면 70.2737 / 62.2698). 구현 전환(ridge_lib→sklearn)은 소수 3자리까지 같은 값(S5)이어서 영향이 확인되지 않았다 (S6 '구현만 전환' 단계는 sklearn import가 정책으로 차단된 실행에서는 미실행). 따라서 6a는 15피처 자신의 CV로 고른 alpha가 아니라 22피처용 alpha를 쓴 값이며, 6단계 설정 값(69.929 / 62.056)이 더 적절한 '15피처 기준'이다. 15→22피처 효과는 6단계 설정 기준 MAE −4.25(cold-start) / −3.74(personalized), 종합표 6a 기준 −4.59 / −3.96이다(후자는 alpha 차이가 섞인 값).

## 5. LSTM 시도 여부 판단
**규칙(결과를 보기 전에 고정)**: history가 가장 긴 구간(120+)의 median-5 대비 MAE 개선폭이 가장 짧은 구간(5-9)보다 크고, 그 차이의 사용자 단위 bootstrap CI가 0을 포함하지 않을 때만 '시도 대상'으로 판단한다. 아니면 '미시도'로 결정한다.

### cold-start
- **7. 직접구현 GBM(주결과)**: 120+ 개선폭=2.712, 5-9 개선폭=1.766, 차이=0.991 (95% CI [-5.199,6.614]) -> 규칙 충족=False
- **8. MLP(주결과)**: 120+ 개선폭=2.351, 5-9 개선폭=3.577, 차이=-1.148 (95% CI [-7.088,3.183]) -> 규칙 충족=False

### personalized
- **7. 직접구현 GBM(주결과)**: 120+ 개선폭=2.861, 5-9 개선폭=1.792, 차이=1.070 (95% CI [-3.604,6.169]) -> 규칙 충족=False
- **8. MLP(주결과)**: 120+ 개선폭=2.867, 5-9 개선폭=3.159, 차이=-0.282 (95% CI [-3.989,3.359]) -> 규칙 충족=False

**사후 추가 baseline의 영향(9단계 보완)**: LSTM 규칙은 median-5 대비 GBM/MLP의 history 구간별 개선폭만 입력으로 쓰므로 사후 추가 baseline 4종은 결정에 영향을 주지 않는다(규칙·결정 불변).

**결론: 미시도.** 규칙을 충족하는 조합이 없었다 — 즉 history가 길어질수록 개선폭이 통계적으로 유의하게 커진다는 근거가 (이 데이터·이 모델들에서는) 확인되지 않았다. 사용자당 세션 수가 적은 사용자가 많다는 점(CLAUDE.md에 이미 명시된 우려)과 일치하는 결과로 보이며, 복잡한 시퀀스 모델을 추가할 근거가 부족하다고 판단해 구현하지 않는다.

## 6. 한계
① **개선폭 크기**: median-5 대비 절대 개선폭은 2.6~3.0초/km(상대 4~5%) 수준으로, 통계적으로는 유의하지만((윈도우 풀링 MAE 기준, 22피처 기준; 사용자별 MAE 평균(macro)에서는 일부 조건에서 CI가 0을 포함하고, cold-start GBM22처럼 점추정이 오히려 높은 경우가 있음 — `docs/same_scope_comparison.md` 7-3절)) 이 크기가 실제 코칭 문구를 바꿀 만큼 큰지는 별개의 판단이다(이미 6~8단계 보고에서 반복 명시).
② **극단 페이스/상위 1% 윈도우 집중**: RMSE 기준 비교의 상당 부분이 상위 1% 오차 윈도우(주로 극단 페이스)에 좌우된다(7단계 세분화 참고, SSE의 90% 이상). RMSE로 순위를 말할 때는 항상 이 전제를 같이 읽어야 한다.
③ **cold-start 초보자(6세션 미만) 제외**: 이 프로젝트의 N=5 설계상 세션 6개 미만인 사용자는 애초에 평가에 들어오지 않는다 — 가장 신규인 사용자에 대한 성능은 이 보고서들이 전혀 말해주지 않는다(미확인, 별도 설계 필요).
④ **날씨/계획 거리 없음**: `docs/feature_availability.md`에서 이미 확인했듯 날씨와 사용자가 입력한 계획 거리는 원본 데이터에 없어 모든 모델이 이 정보 없이 학습됐다 — 이게 성능 상한을 얼마나 낮추는지는 **미확인**이다.
⑤ **직접 구현 GBM과 sklearn 환경 이슈**: sklearn.tree의 import 성공 여부가 실행마다 달라지는 간헐적 현상을 7단계 보완에서 발견했고(원인 미확인), 재현성을 위해 import 성공 여부와 무관하게 `gbt_lib.py`(numpy 직접구현)를 고정 사용하도록 고쳤다. 이 환경의 근본 원인(Application Control Policy의 캐시/타이밍 문제로 추정)은 검증하지 않았다 — 다른 환경/다른 시점에 재현했을 때 실제 sklearn.HistGradientBoostingRegressor 결과와 수치가 얼마나 다를지는 **미확인**이다(0-1/0-2절 비교 참고, 직접 대조는 못 했음).
⑥ **입력 정보량이 병목일 수 있다는 것은 가설**: Ridge/GBM/MLP가 서로 성능이 비슷하고(통계적으로 구분 안 되는 경우가 많음) median-5 대비 개선폭도 비슷한 크기라는 점은 '모델 구조보다 입력 피처(과거 5세션 요약)가 성능을 제한하는 병목일 수 있다'는 가설과 일치하지만, 이를 직접 검증(예: 피처를 늘렸을 때 성능이 계속 오르는지 체계적으로 확인)하지는 않았다 — **추정/미확인**이다.
