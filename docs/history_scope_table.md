## 2. 22피처의 구성 (`24_build_xy_dataset_extended.py:62-78`)
- 앞 15개: 과거 5세션 각각의 `actual_distance_km`, `avg_pace_sec_per_km`, `avg_heart_rate`.
- 뒤 7개: `median_past5_elapsed_pace`, `median_past5_moving_pace`, `median_past5_stop_ratio`(5회 범위), **`user_history_median_pace`(타깃 이전 전체 이력, 상한 없음)**, `past5_pace_mad`(5회), `days_since_last_session`(`:133`), **`cumulative_session_count`(= 타깃 세션의 session_order, 타깃 이전 전체 세션 수; `:134`)**.
- 따라서 **22피처 모델(Ridge22/GBM22/MLP22)은 "최근 5회만"이 아니라 전체 이력 정보(전체 이력 중앙값, 누적 세션 수)를 입력으로 받는다.** 그래서 15피처 모델과 같은 선에서 순위를 매기지 않고, 그룹 (a) / (b)로 나눠 같은 입력 범위 안에서만 비교한다.

## 3. 시간 경계 검증 (타깃 시작 이전 세션만 쓰는가)
- 마지막 입력 세션 종료 < 타깃 시작: 윈도우 생성 시 위반하면 제외(`24:113-117`), 전체 샘플에 대해 `assert min(gaps) > 0`(`24:237`).
- 전체 이력 중앙값: `expanding().median().shift(1)`로 자기 자신을 제외한 이전 세션만 사용(`24:86-87`). 참조한 세션 중 가장 늦은 종료 시각이 타깃 시작 이후면 윈도우를 제외한다(`24:119-122`) — assert가 아니라 제외+건수 기록 방식이다.
- median-10/20: `session_order < target_session_order` 위치 슬라이싱(`28:106-117`). 위치==session_order 전제는 3주차 4번에서 `build_pace_by_user`에 assert로 추가했다(`28:93-103`): 사용자별 `session_order == 0..n-1`, 시작 시각 비감소. 이 윈도우들은 전체 이력 감사(`24:119-122`)를 이미 통과한 것들이다.
- (d): 위 두 입력의 조합이라 새 시간 경로가 없다.

## 4. cold-start 정의 (정정)
**학습에 없던 사용자이지만 타깃 이전 기록이 5회 이상 있는 조건**이다. 입력은 그 사용자의 직전 5회이고, 전체 이력 중앙값·누적 세션 수 피처는 5회보다 더 먼 과거까지 사용한다(`24:200-203`, 학습은 train 사용자 윈도우만 `25:354`, `27:266`, `28:169`). 기록이 전혀 없는 신규 사용자는 평가에 없다. (이전 문구 "학습에 없던 사용자이지만 과거 5회 기록은 있는 조건"은 전체 이력 피처를 설명하지 못해 정정했다.)
