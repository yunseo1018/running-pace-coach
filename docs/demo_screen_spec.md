# 시연 출력 "요약 화면 + 자세히 보기" 사양 (구현 전 고정)

대상: `demo/coach_demo.py`의 출력 구성. **보이는 순서와 묶음만 바꾼다.** B2 계산식·파라미터·명목 80% 범위·조건별 안내 규칙(층과 수치)·상태 판정(`[입력 부족]`, `[조건별 검증 부족: 개발 결과 기준 경고]`, `[결과 미관측]`의 조건)·피드백/목표 비교 규칙·`--log`/`--resolve`는 바꾸지 않는다.

## 1. 기본 출력: 요약 화면 (10줄 안팎)

머리표 `[결과]`, `[상태]`, `[안내]`, `[근거]`(예측 불가이면 `[해결]`), `[주의]` 순서. 이어지는 줄은 머리표 폭만큼 들여쓴다.

| 머리표 | 내용 |
|---|---|
| `[결과]` | ① `다음 7일 안 5km 예상 기록: mm:ss / 명목 80% 범위 mm:ss ~ mm:ss` ② `다음 7일 안 적격 5km 기록이 관측되는 경우에 대한 예측입니다(명목 80% 범위)` ③ `실측 포함률 75.3%(cold-start test, 탐색 결과), 개인에게 80%를 보장하지 않음`. 예측이 없으면(`[입력 부족]`) `예측할 수 없습니다(자격 미달).` |
| `[상태]` | 해당하는 것을 공백으로 이어 쓴다: `[입력 부족]` / `[조건별 검증 부족: 개발 결과 기준 경고]`(조건별 안내가 하나라도 있을 때) / `[결과 미관측]`(`--feedback`에서 7일이 지났는데 적격 기록이 없을 때). 하나도 없으면 `특이 조건 없음`. 판정 조건은 이전 사양(`docs/prospective_log_spec.md` 3절)과 같다. |
| `[안내]` | 조건별 안내를 **한 줄씩**: `<조건>: 학습 자료 교차검증 포함률 NN.N%(N건/N명, 개발 결과)`. 관측 수·사용자 수는 `demo/stratum_notes.json`의 값이다. 이어서 `정지 시간 정보가 없어 이 조건은 확인하지 않았습니다`(해당할 때), 입력 알림(미래 날짜·중복 기록 제외, 기준 시점 이후 기록 제외, 기준 기록 대체 등). 아무것도 없으면 `조건별 안내 없음`. 예측이 없으면 `부족한 조건: …`을 한 줄씩. |
| `[근거]` | `평소 mm:ss, 직전 mm:ss → 예상 변화 약 ±N초(기본 변화량 ±a초 + 평소 대비 보정 ±b초)` 한 줄. |
| `[해결]` | 예측이 없을 때 `[근거]` 대신: `…를 CSV에 추가하거나 기록이 충분한 기준 시점(--asof)을 지정하면 예측할 수 있습니다.`(명령형이 아닌 문장; 정정 이력 참고) |
| `[주의]` | `원인 분석·훈련 처방이 아닙니다. --detail로 계산 과정과 근거 문서를 볼 수 있습니다.` |

- 요약 화면 뒤에 `--goal`, `--feedback` 블록이 **같은 형식**(머리표 한 줄 + 핵심 2~3줄)으로 이어진다. 목표 비교: `[목표 비교] 목표 mm:ss: <명목 범위 안/보다 빠름/보다 느림>` + 예측 − 목표 차이 한 줄 + 달성 확률·훈련 처방이 아님을 알리는 한 줄. 피드백: `[뛴 다음의 피드백] …` + 실제 기록·차이·범위 대비 위치 한 줄, 학습 자료 기준 비율 한 줄(또는 비교 불가 사유), 고정 문장 한 줄(`범위 안·밖은 실력 변화의 증거가 아니며, 한 번의 기록에는 일상적인 흔들림이 포함됩니다.` + `이 비교는 1회 관측이며 예측 성능의 근거가 아닙니다.` 두 문장 그대로).
- `--log`가 있으면 맨 끝에 저장 안내 한 줄(기존과 같음).
- 요약 화면의 모든 숫자는 같은 계산값에서 나온다: 요약 속 숫자 토큰이 자세히 보기(기존 전체 출력)와 `stratum_notes.json`에 있는 값만으로 이루어졌음을 자동 검사한다.

## 2. `--detail`: 자세히 보기

요약 화면 뒤에 구분선 `───── 자세히 보기(--detail) …` 아래로 **기존 출력(요약 도입 이전의 전체 출력)을 한 글자도 바꾸지 않고** 그대로 보여 준다(두 항의 방향 문장, 통계적 현상 문구, 근거 문서, 범위 폭 불변 안내, 목표·피드백의 설명 문장 포함). `[주의]` 줄의 안내만 "아래 자세히 보기에 …"로 바뀐다. `--resolve`에서 `--detail`은 기존대로 줄별 상태 표시다.
기존 전체 출력은 `run_full`이 만들며 `demo/examples/*.full.txt`에 요약 도입 직전의 출력을 고정해 두었다. 테스트가 (a) `run_full` 출력 = `*.full.txt`, (b) `*.full.txt`의 모든 줄이 `--detail` 출력에 그대로 들어 있음을 확인한다. 즉 기존 문장이 빠지지 않는다.

## 3. 요약 화면에 반드시 남아야 하는 문구 (테스트로 고정)

| 항목 | 고정 문구(부분 문자열) | 적용 |
|---|---|---|
| 조건부 예측 문구 | `다음 7일 안 적격 5km 기록이 관측되는 경우에 대한 예측` | 예측이 있을 때 |
| 명목 범위 | `명목 80% 범위` | 예측이 있을 때 |
| 실측 포함률 | `실측 포함률 75.3%(cold-start test, 탐색 결과)` | 예측이 있을 때 |
| 개인 보장 아님 | `개인에게 80%를 보장하지 않음` | 예측이 있을 때 |
| 상태 표시 | `[상태]` 줄 + (`[입력 부족]` / `[조건별 검증 부족: 개발 결과 기준 경고]` / `[결과 미관측]` / `특이 조건 없음` 중 해당하는 것) | 항상 |
| 원인·처방 아님 | `원인 분석·훈련 처방이 아닙니다` | 항상 |

- 목표 비교 블록에는 `달성 확률이나 달성 가능 여부를 뜻하지 않으며, 훈련 처방을 제공하지 않습니다`, 피드백 블록에는 위 두 고정 문장이 남는다.
- 금지 표현 테스트(`docs/demo_feedback_spec.md` 7절의 목록)는 피드백 블록·`--resolve` 출력에 그대로 유지하고, 요약 화면의 예시 출력 전체에도 적용한다. 단 "원인·처방이 아님"을 알리는 부정 문장(`[주의]` 줄, 목표 비교의 `달성 확률이나 달성 가능 여부를 뜻하지 않으며, 훈련 처방을 제공하지 않습니다`)은 제외한다.

### 정정 이력 (금지 표현 예외 목록)
1. 처음 사양: 요약 화면 전체에 금지 표현 테스트를 적용한다고만 적었으나 `[주의]`의 "원인 분석·훈련 처방이 아닙니다"가 목록과 겹쳐 모순이었다(구현 중 정정, 커밋 `1880a15`): `[주의]`·목표의 부정 문장과 입력 부족의 `[근거] 해결:` 줄(기존 문구의 "…지정하세요")을 예외로 두었다.
2. 정리 커밋: 입력 부족 화면의 `[근거]` 칸을 `[해결]` 칸으로 바꾸고 문장을 명령형이 아닌 "…를 CSV에 추가하거나 기록이 충분한 기준 시점(--asof)을 지정하면 예측할 수 있습니다."로 바꿨다. 그래서 **`[근거] 해결:` 예외를 목록에서 뺐다**(예외는 부정 문장 두 가지뿐). 자세히 보기(기존 전체 출력)의 `해결:` 줄은 기존 문구 그대로다.
- `personalized` 포함률은 어디에도 쓰지 않는다(독립 평가가 아님).

## 5. 예시 ①: 기존 출력과 새 요약 화면

`demo/examples/ex1_steady.csv`, 기준 시점 2025-03-03. 테스트가 아래 두 블록이 실제 출력과 같음을 확인한다. 기존 출력은 새 구조에서 `--detail`의 "자세히 보기"에 그대로 들어간다.

### 기존 출력 (13줄)

```text
다음 7일 안 5km 예상 기록: 24:41 / 명목 80% 범위 21:19 ~ 29:19
다음 7일 안 적격 5km 기록이 관측되는 경우에 대한 예측입니다(명목 80% 범위)
실측 포함률 75.3%(cold-start test, 탐색 결과), 개인에게 80%를 보장하지 않음
평소 기록(과거 중앙값): 24:56, 직전 기록: 24:59
예상 변화 약 −18초 = 기본 변화량 a(−15.3초) + 평소 대비 보정 b×(직전 − 평소)(−2.5초)
직전 기록이 평소와 같았던 경우, 학습 데이터에서 다음 7일 첫 5km 변화의 중앙값은 약 −15초였음(상관, 인과 아님).
직전 기록이 평소보다 3초 느렸던 만큼 보정 항(−2.5초)이 평소 쪽(빠른 쪽)으로 움직였고, 기본 변화량(−15.3초)도 같은 방향이라 최종 예측은 직전 기록보다 18초 빠릅니다. (기록이 평소 주위에서 흔들리는 통계적 현상이며, 원인 효과가 아님)
현재 자료로는 지난 4주의 거리·횟수 정보가 이 예측을 더 좋게 만든다는 뚜렷한 증거를 확인하지 못해 평균 회귀 규칙만 사용합니다. 근거: 최종 평가 결과(docs/final_results_5km.md)
이 예측은 원인 분석이 아니며, 주마다 기록이 크게 흔들릴 수 있습니다.
[조건별 검증 부족: 개발 결과 기준 경고] train 폴드 밖 개발 결과 기준이며 새 자료로 확인되지 않았습니다
※ 이 조건(과거 유효 5km가 2~4개뿐)에서는 학습 자료 교차검증에서 명목 80% 범위의 실제 포함률이 73.1%였습니다. 범위를 더 넓게 보셔야 합니다.
※ 위 안내는 범위 폭을 바꾸지 않습니다(명목 80% 범위는 모든 조건에서 같은 폭입니다).
※ 정지 시간 정보가 없어 이 조건은 확인하지 않았습니다
```

### 새 요약 화면 (8줄, 기본 출력)

```text
[결과] 다음 7일 안 5km 예상 기록: 24:41 / 명목 80% 범위 21:19 ~ 29:19
       다음 7일 안 적격 5km 기록이 관측되는 경우에 대한 예측입니다(명목 80% 범위)
       실측 포함률 75.3%(cold-start test, 탐색 결과), 개인에게 80%를 보장하지 않음
[상태] [조건별 검증 부족: 개발 결과 기준 경고]
[안내] 과거 유효 5km가 2~4개뿐: 학습 자료 교차검증 포함률 73.1%(308건/209명, 개발 결과)
       정지 시간 정보가 없어 이 조건은 확인하지 않았습니다
[근거] 평소 24:56, 직전 24:59 → 예상 변화 약 −18초(기본 변화량 −15.3초 + 평소 대비 보정 −2.5초)
[주의] 원인 분석·훈련 처방이 아닙니다. --detail로 계산 과정과 근거 문서를 볼 수 있습니다.
```
