# 시연 조건별 범위 안내 사양 (결과 계산 전에 고정)

작성: 11월 1주차. 시연(`demo/coach_demo.py`)에 **조건별 안내 줄**을 추가하는 사양이다. **B2 계산식·파라미터·명목 80% 범위(위치와 폭)는 바꾸지 않는다.** 조건별로 범위 폭을 다르게 하는 것은 이번에 하지 않는다. 이 문서는 구현 전에 고정한다.

## 1. 근거 자료

- **`docs/b2_failure_5km.md`의 train 폴드 밖 결과만** 쓴다(사양 `docs/posthoc_spec_b2_failure_5km.md`, 커밋 f5ba594, 실행 c5e77f3). **test 숫자는 안내 줄에 쓰지 않는다**(test는 이미 열람한 탐색 결과). 화면의 기존 "테스트 포함률 xx%(탐색 결과)" 줄은 이번 변경 대상이 아니며 그대로 둔다.
- 안내의 숫자(포함률)는 위 문서의 train 폴드 밖 행에서 **읽어서** 채운다. 구현은 `demo/make_stratum_notes.py`가 문서의 표를 읽어 `demo/stratum_notes.json`을 만들고(산출 파일), 시연은 이 JSON을 읽는다. 테스트가 문구·값과 문서·선정 규칙이 맞는지 확인한다.

## 2. 안내를 띄울 층의 선정 규칙과 목록 (고정)

- **선정 규칙**: `docs/b2_failure_5km.md`의 **train 폴드 밖** 층 가운데 **평가 대상이 30개 이상(표본 부족 아님)이고 명목 80% 범위 포함률의 95% CI 상한이 80% 미만**인 층.
- **층 목록(현재 규칙 적용 결과, 고정)** — 4개:

| 차원 | 층 | 평가 대상 / 사용자 | train 폴드 밖 포함률 [95% CI] |
|---|---|---|---|
| (a) 과거 유효 5km 개수 | 1개(x = 0) | 109 / 109 | 70.6% [61.5%, 78.9%] |
| (a) 과거 유효 5km 개수 | 2~4개 | 308 / 209 | 73.1% [67.5%, 78.2%] |
| (b) \|T5(기준) − m\| | 120초 초과 | 556 / 180 | 67.8% [61.9%, 73.8%] |
| (e) 기준 기록 세션 안 정지 시간 | 300초 초과 | 87 / 45 | 39.1% [28.7%, 49.2%] |

  나머지 12개 층은 CI 상한이 80% 이상이라 안내하지 않는다(예: (e) 60초 초과 ~ 300초 이하 [61.4%, 80.6%]).
- **이력**: 처음 지시의 층 목록에는 (a) 2~4개가 빠져 있었다(3개). 선정 규칙을 문서에 적용하면 (a) 2~4개도 해당하므로 **규칙 적용으로 바로잡아 4개로 고정**했다(사용자 확인). 이에 따라 "해당 없는 예시 ①의 출력은 바뀌면 안 된다"는 조건은 취소됐고 예시 ①(과거 유효 5km 4개)에는 (a) 2~4개 안내 줄이 추가된다. 안내 줄이 하나도 뜨지 않는 합성 예시를 따로 추가한다(과거 유효 5km 5개 이상, |T5(기준) − m| 120초 이하, 정지 시간 300초 이하).
- 이 선정 규칙과 목록은 결과를 보고 바꾸지 않는다. 문서가 다시 만들어져 선정 결과가 달라지면 사양을 먼저 갱신하고 커밋한다(JSON 재생성 스크립트가 목록이 4개와 다르면 중단한다).

## 3. 화면에서의 조건 판정 (예측 시점에 관측 가능한 값만)

| 층 | 판정 조건 | 입력 |
|---|---|---|
| (a) 1개(x = 0) | 기준 시점 이전에 끝난 유효 5km(기준 기록 포함) 개수 = 1 | CSV의 5km 기록 |
| (a) 2~4개 | 같은 개수가 2 이상 4 이하 | 〃 |
| (b) 120초 초과 | \|기준 기록 − 평소 기록(m)\| > 120초(반올림 전 값) | 기준 기록, m |
| (e) 300초 초과 | 기준 기록 세션의 정지 시간 > 300초 | CSV의 `stop_sec` 열 |

- 해당하는 층이 여러 개이면 **해당하는 줄을 모두** 표시한다. 순서는 (a), (b), (e). ((a) 1개이면 x = 0이므로 (b)는 겹치지 않는다.)
- 안내 줄은 예측 문구 뒤에 붙이고(목표 비교 블록 앞), 해당 층이 하나도 없으면 아무 줄도 추가하지 않는다.
- JSON에 다른 층이 선정돼도(예: (c), (d)) 대응하는 판정 조건과 문구를 코드에 모두 정의해 두어 규칙대로 동작하게 한다(현재 선정은 위 4개).

## 4. 화면 문구 (고정)

각 층의 줄: **"※ 이 조건(<조건>)에서는 학습 자료 교차검증에서 명목 80% 범위의 실제 포함률이 <XX.X>%였습니다. 범위를 더 넓게 보셔야 합니다."**

| 층 | <조건> |
|---|---|
| (a) 1개(x = 0) | 과거 유효 5km가 직전 기록 1개뿐 |
| (a) 2~4개 | 과거 유효 5km가 2~4개뿐 |
| (b) 120초 초과 | 직전 기록이 평소와 2분 넘게 차이 |
| (e) 300초 초과 | 직전 기록 세션에 5분 넘는 정지가 있음 |

- <XX.X>는 `docs/b2_failure_5km.md` train 폴드 밖 행의 포함률(소수 1자리, 문서 표기 그대로)이다.
- 안내 줄이 하나라도 있으면 그 뒤에 한 줄을 덧붙인다: **"※ 위 안내는 범위 폭을 바꾸지 않습니다(명목 80% 범위는 모든 조건에서 같은 폭입니다)."**
- 이 안내는 교차검증 통계(상관)이며 개인에게 80%를 보장하지 않는다는 기존 문구는 그대로다. 훈련 처방이나 원인 설명이 아니다.

## 5. (e) 정지 시간 입력

- 입력 CSV에 **선택 열 `stop_sec`**(단위 초)를 둔다. 값은 그 세션의 점 기록에서 **시간차가 0보다 크고 속도가 1km/h 미만인 점 사이 구간의 시간 합**(세션 전체; `docs/posthoc_spec_b2_failure_5km.md` 5절 3과 같은 정의)이다. 5km 기록(기준 기록 후보)에만 필요하고 그 외 행은 비워도 된다. 값은 0 이상의 숫자여야 하며 아니면 입력 오류로 안내한다("오류/해결" 두 줄).
- **열이 없거나 기준 기록 세션의 `stop_sec`가 비어 있으면** (e) 안내 줄은 띄우지 않고 **"※ 정지 시간 정보가 없어 이 조건은 확인하지 않았습니다"**를 표시한다(JSON에 (e) 층이 선정돼 있을 때만).
- 기존 CSV(6개 열)는 그대로 동작한다.

## 6. 테스트 (문구와 값이 맞는지 확인)

- JSON의 층 목록과 포함률이 `docs/b2_failure_5km.md` train 폴드 밖 행·선정 규칙(표본 30개 이상, CI 상한 80% 미만)과 일치하고 위 4개 층이다.
- 각 층의 판정 경계(과거 5km 1·2·4·5개, |x| 120.0과 120보다 큼, 정지 300과 300보다 큼)에서 줄이 뜨고 안 뜨는지, 여러 층이 겹치면 줄이 모두 뜨는지, 줄의 숫자가 JSON 값과 일치하는지, (e) 정보가 없을 때 문구가 나오는지.
- 안내 줄이 없는 합성 예시의 출력에 "※ 이 조건" 줄이 없고, 예시 출력 파일이 실제 실행 결과와 같다.
- 모든 기존 테스트와 `46_fill_readme.py --check`를 통과한다.
