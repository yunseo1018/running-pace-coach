# 시연 "뛴 다음의 피드백" 사양 (구현 전 고정)

대상: `demo/coach_demo.py --feedback`, `demo/make_feedback_quantiles.py`, `demo/feedback_quantiles.json`.
B2 계산식·파라미터(`demo/b2_params.json`)·명목 80% 범위는 바꾸지 않는다. 이 문서는 구현 커밋보다 먼저 커밋한다.

## 1. 목적과 범위

기준 시점(`--asof`)에 한 예측과, 그 뒤 7일 안에 실제로 뛴 첫 5km 기록을 비교해 **실제 기록이 예측 범위의 어디에 있는지**를 근거 있는 숫자로 알려 준다.
처방, 원인 설명, 실력 변화 판정, 목표 달성 확률은 하지 않는다. 비교는 "다음 7일 안에 5km 기록이 관측된 경우"에 조건부다.

## 2. 사용법

```
python demo/coach_demo.py <CSV> --asof <시점> --feedback [--goal mm:ss]
```

- 예측 부분은 `--feedback` 없이 실행한 출력과 **글자 그대로 같다**(기준 시점 이전에 끝난 기록만 사용). 피드백 블록은 그 뒤(목표 비교 블록이 있으면 그 다음)에 빈 줄을 두고 붙인다.
- `--feedback`이 없으면 출력은 지금과 글자 그대로 같다(테스트로 고정).
- 기존 조건별 안내(과거 5km 개수, 평소와 2분 넘게 차이, 정지 5분 초과)는 예측 부분에 그대로 둔다.
- 예측이 불가능한 경우(자격 미달)에는 피드백 블록에 "예측이 없어 비교하지 않습니다"만 쓰고 고정 문장은 그대로 출력한다.

## 3. 비교 대상(실제 기록)

- 후보: 시작 시각이 `[asof, asof + 7일)`이고, 거리가 5.0~5.5km이며, `t5_sec`가 있는 달리기.
- 그중 **시작이 가장 이른 것**이 비교 대상이다. 연구 정의와 맞추기 위해 극단(T5 > 5,000초)도 제외하지 않는다.
- 비교 대상보다 먼저 뛴 5.0~5.5km 기록 중 `t5_sec`가 없어 건너뛴 것이 있으면 그 개수를 표시한다.
- 현재 시각 이후의 기록(미래 날짜)은 기존 규칙대로 입력 단계에서 제외된다.

## 4. 비교 불가

- 비교 대상이 없으면 "다음 7일 안에 비교할 5km 기록이 없습니다"를 출력한다.
- `asof + 7일`이 현재 시각보다 뒤이면(7일이 아직 지나지 않음) "아직 7일이 지나지 않았습니다"를 덧붙인다. 비교 대상이 이미 있으면 가장 이른 기록이 정해졌으므로 이 문구 없이 비교한다.
- 5.0~5.5km 기록은 있으나 모두 `t5_sec`가 없으면 그 개수를 덧붙인다.
- 모든 경우에 "이 비교는 다음 7일 안에 5km가 관측된 경우에 한합니다"를 표시한다.

## 5. 출력 항목(비교 가능한 경우)

1. 실제 기록: 날짜(start_time의 날짜), 5km 시간(T5, mm:ss).
2. 예측(예상 기록과 명목 80% 범위): 예측 부분과 같은 값.
3. 차이(실제 − 예측, 초): 음수 = 예측보다 빠름. 정수 초로 계산한다(`round(실제) − round(예측)`, 화면의 mm:ss와 같은 반올림).
4. 명목 범위 대비 위치: `round(실제)` 기준 "범위보다 빠름 / 범위 안 / 범위보다 느림"(`--goal` 비교와 같은 반올림 규칙).
5. 학습 자료 기준 드문 정도(차이가 0이 아닐 때만):
   - 실제가 예측보다 빠르면 "학습 자료에서 예측보다 {|차이|}초 이상 빨랐던 경우: x%".
   - 느리면 같은 방식으로 "이만큼 이상 느렸던 경우: x%". x는 소수 1자리.
   - 차이가 0이면 "예측과 같음"만 쓰고 x%는 쓰지 않는다.
6. 고정 문장(비교 불가인 경우에도 항상 출력):
   - "범위 안·밖은 실력 변화의 증거가 아니며, 한 번의 기록에는 일상적인 흔들림이 포함됩니다."
   - "이 비교는 1회 관측이며 예측 성능의 근거가 아닙니다."

## 6. x%의 근거

- 자료: 범위 보정(`scripts/55_interval_calibration_5km.py`, 사양 `docs/interval_calibration_spec_5km.md`)과 같은 **train 사용자 단위 GroupKFold(5, seed 42)** 폴드 밖 B2 잔차(= 실제 변화 − 예측 변화 = 실제 T5 − 예측 T5). 폴드마다 학습 폴드에서 LAD로 (a, b)를 적합하고 폴드 밖 잔차를 모은다(train 1,720개·278명). **test 자료는 쓰지 않는다.**
- 잔차 원값은 저장하지 않는다. 1%~99% 분위수 99개를 `demo/feedback_quantiles.json`에 저장하고(소수 3자리, 사용자 ID·행 정보 없음), 분위수 사이는 선형 보간한다.
- 계산: 누적비율 F(d)를 분위수 표의 선형 보간으로 구한다. 빠른 쪽 x = F(d)(잔차 ≤ d), 느린 쪽 x = 1 − F(d)(잔차 ≥ d), d는 차이(정수 초). 1% 분위수보다 더 빠르거나 99% 분위수보다 더 느리면 정확한 값을 알 수 없으므로 "1% 미만"으로 쓴다.
- 이 값은 분위수 표 전체(조건 구분 없는 전체 train)의 분포이며, 조건별(과거 5km 개수 등) 분포가 아니다. 개인에게 맞는 확률이 아니며 해석은 "학습 자료에서 그런 경우의 비율"에 한정한다.
- 생성: `python demo/make_feedback_quantiles.py`(저장소 루트, 로컬 `data/5km_dataset_train.pkl` 필요). 생성 스크립트는 q10·q90이 `demo/b2_params.json`의 `resid_q10`·`resid_q90`와 일치하는지 assert하고 어긋나면 파일을 쓰지 않는다.
- 재생성 확인: 스크립트를 다시 실행한 뒤 `git diff --exit-code demo/feedback_quantiles.json`이 비어 있어야 한다(결정적: seed 고정, 난수 없음).
- 코드의 보간 함수는 표준 라이브러리만 쓴다(`coach_demo.py`).

## 7. 금지 표현(출력의 피드백 블록에 쓰지 않는다)

테스트가 아래 목록의 부분 문자열이 피드백 블록에 없음을 확인한다.

- 훈련·휴식 권고: "훈련", "휴식", "쉬", "권장", "추천", "하세요", "해야", "늘리", "줄이"
- 실력 변화 판정: "늘었", "줄었", "향상", "좋아졌", "나빠졌", "나아졌", "퇴보", "저하"
- 목표 달성 확률: "확률", "달성"
- 원인 설명: "때문", "원인", "덕분", "탓", "결과로"

(고정 문장의 "실력 변화의 증거가 아니며"는 판정이 아니라 판정하지 않는다는 부정 표현이라 목록에 넣지 않는다. 위 단어 중 고정 문장에 들어 있는 것은 없다.)

## 8. 테스트(합성 데이터)

범위 안 / 범위보다 빠름 / 범위보다 느림 / 비교할 기록 없음 / 7일 미경과 / t5 없는 5km를 건너뛴 경우 / 분위수 보간값 / 금지 표현 없음 / `--feedback` 없을 때 출력 불변 / 극단(T5 > 5,000초)도 제외하지 않음 / 분위수 JSON의 형식(99개, 단조 증가)과 `b2_params.json`의 q10·q90 일치.
합성 예시 2개(범위 안 1개, 범위보다 빠름 1개)를 `demo/examples/`에 추가하고 README 시연 절과 `46_fill_readme.py --check`를 맞춘다.

## 9. 내 실제 기록 점검(커밋하지 않음)

로컬 개인 CSV로 과거 월요일(00:00) 중 예측 가능한 기준 시점 전부에 `--feedback`을 적용해 "비교 가능 시점 수 / 비교 불가 시점 수(이유별)"만 집계한다. 개별 날짜·기록 값은 출력하지 않는다. 결과는 문서에 싣지 않고 보고에만 쓴다.

## 10. 변경하지 않는 것

B2 식과 파라미터, 명목 80% 범위(폭과 위치), 조건별 안내, `--feedback` 없는 출력, 연구 문서의 결론(49c02f8 범위).
