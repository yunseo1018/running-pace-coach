# 사후 탐색 결과: 최근 기간 기준치 B2r (5km 과제)

생성: `scripts/60_recent_m_5km.py`. 사양: `docs/posthoc_spec_recent_m.md`(커밋 5f3be15, 결과 계산 전 고정). **사후 탐색**이며 상관관계까지만 주장한다. 선택은 train 폴드 밖(개발)으로만 했고 test cold-start(352개·71명)는 **선택에 쓰지 않았으나 이미 열람한 자료의 탐색 결과**다. 주 결론(49c02f8)·B2 시연(식·파라미터)·명목 80% 범위·조건별 안내 규칙은 **바꾸지 않았다**. 모든 평가는 "다음 7일 안에 적격 5km 기록이 관측된 경우"에 조건부다. ID·행 값은 싣지 않았다.

- B2r: B2와 같은 식에서 m 대신 m_W(t 이전에 끝난 최근 W일 안 유효 5km의 T5 중앙값). 사용자 평균 MAE의 단위는 초이고 차이가 음수이면 B2r 쪽이 낮다.
- 개발 자료 = train 1,720개·278명, 사용자 단위 GroupKFold(5, seed 42), 폴드마다 학습 부분에서 a·b를 다시 적합한 폴드 밖 예측. 구현 세부: 두 규칙(대체/보류) 모두 a·b는 n_W ≥ k인 행에서 적합하고, 대체는 같은 a·b를 전체 기간 m의 x에 적용한다(그래서 n_W ≥ k인 행에서 두 규칙의 예측이 같다).
- **검증(assert)**: B2의 폴드 밖 잔차가 55번 결과와 같고 q10·q90이 `demo/b2_params.json`과 같음, B2 train 전체 적합 a = -15.287, b = -0.7912가 시연·49c02f8과 같음, B2 test 예측이 저장된 49c02f8 예측과 같고 사용자 평균 MAE 235.117가 `docs/final_results_5km.md`와 같음, 개발 자료 B2 사용자 평균 MAE 209.3가 `docs/b2_failure_5km.md`와 같음, 전체 기간 m 재계산이 데이터셋의 m과 같음.
- 사용자 단위 bootstrap: 사용자 복원추출 2,000회, seed 42, 백분위 95% CI(모든 비교에 같은 추출). 사용자별 차이는 그 사용자의 비교한 시점들의 평균 MAE 차이다.

## 선택된 설정 (개발 자료만으로)

- **W = 365일, k = 2, 규칙 = 대체**. 선택 점수(두 규칙이 모두 예측하는 행에서 사용자별 (B2r MAE − B2 MAE)의 평균) = +0.347초.
- 두 규칙의 예측은 n_W ≥ k인 행에서 같아 점수가 같으므로 사양대로 동률 규칙(대체: 예측 가능 시점을 줄이지 않음)을 택했다. 보류 규칙은 비교용으로 함께 보고한다.
- 기록이 있는 한 기준 기록은 항상 직전 28일 안에 있어 W ≥ 28이면 n_W ≥ 1이다. 그래서 k = 1이면 두 규칙 모두 모든 시점을 예측한다(n_W < 1이 없음).
- **후보를 9개(규칙 포함 18개 조합) 보고 하나를 골랐으므로 개발 자료의 개선은 선택 편향으로 우연일 수 있다.**

## 해석 (사양 4절의 규칙)

- 개발 자료 (a): 대체(선택) 평균 차이 +0.592 [-2.982, 4.124] → **우열 확정 불가(동등성 입증 아님)**. test(탐색): +2.744 [-2.118, 8.644] → **우열 확정 불가(동등성 입증 아님)**.
- 9개 후보 모두 개발 자료의 선택 점수가 양수였다(가장 낮은 점수 +0.347초; 같은 행에서 B2r의 점추정이 B2보다 높음). 어느 후보도 B2보다 낮은 점추정을 보이지 않았다.
- 후보를 9개(규칙 포함 18개 조합) 보고 하나를 골랐으므로 선택된 설정의 개발 자료 값은 낙관적이며 우연일 수 있다. test는 선택에 쓰지 않았지만 이미 열람한 자료의 탐색 결과다.
- **이 결과로 시연(B2, 범위, 안내)과 기존 결론(49c02f8)을 바꾸지 않는다.** 개선돼 보이더라도 새 자료로 확인하는 향후 과제로만 둔다. B2r이 B2보다 낫다고 쓰지 않으며, 최근 기간을 쓰는 것이 원인이라고 해석하지 않는다.
