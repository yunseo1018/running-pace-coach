# 10월 5주차 5km 타깃 비교 가능성 점검 (교수 피드백 반영 1단계)

생성: `37_target_feasibility.py` (읽기 전용·개수와 가능 여부만). **기록 시간·기록 변화량·페이스의 분포·평균 등 결과값은 계산하지 않았다.** 5km 지점 도달 시각 자체는 계산·저장하지 않았고, 사용자/세션 ID·좌표·행 값은 싣지 않았다. start_time은 "원값(기준 미확인)"이며 월요일 00:00 격자는 그 원값을 UTC로 해석한 가정이다(`docs/week4_data_audit.md` 6절 "판정 불가"). 5km 세션은 한 번 달린 거리가 4.5~5.5km인 세션(병합 후 세션 단위)이며, 5.0~5.5km 정의는 B절에서 따로 본다.

## A. 정확한 5km 구간 추출 가능성

### A-1. 방법과 01번 거리 계산과의 일치

원본 기록에는 점마다 `timestamp`·`latitude`·`longitude`가 있다(`01_parse_run_sessions.py:build_session_row`가 같은 배열을 읽는다). 누적 haversine 거리가 5.000km에 처음 도달하는 두 점 사이를 선형 보간하면 도달 시각을 구할 수 있다(가능). 단 `01_parse_run_sessions.py:total_distance_km`는 점 간 시간차 ≤ 0이거나 암시 속도가 임계를 넘는 구간(GPS 점프)의 거리를 누적에서 뺀다. 따라서 보간은 **같은 규칙의 누적 거리**(스킵 구간은 0 누적)로 해야 세션 표의 `actual_distance_km`와 같은 기준이 된다. 아래 점검은 그 규칙으로 직접 구현해 확인한 결과다.

| 항목 | 값 |
|---|---|
| 점검 대상 원본 기록(4.5~5.5km 세션 및 병합 구성 조각) | 10,460 |
| 원본에서 찾아 같은 규칙으로 누적 거리를 다시 계산한 기록 | 10,460 |
| 재계산 총 거리가 세션 표(중복 제거 후 조각) 거리와 1e-9km 넘게 다른 기록 | 0 |

### A-2. 5.0km 이상 여부별 개수

| 구분 | 건수/사용자 |
|---|---|
| 4.5~5.5km 세션 전체 | 10,021건 / 697명 |
| └ 5.0km 이상 (5.000km 지점이 세션 안에 있음 → 정확 추출 가능) | 5,521건 / 625명 |
| └ 5.0km 미만 (정확 추출 불가) | 4,500건 / 596명 |
| 참고: 길이 무관 5.0km 이상 모든 러닝 세션 | 81,997건 / 828명 |

5.0km 이상 세션에서만 "세션 안의 5.000km 지점"이 존재하므로, 4.5~5.0km 세션은 정확한 5km 구간 시간을 만들 수 없고 5km 환산 시간(경과 시간÷거리×5)만 가능하다. 5.0~5.5km 정의는 이 정확 추출 가능 세션만 5km로 인정하는 경우다.

### A-3. 점 간 시간 간격 (보간 정밀도 판단용)

| 대상 | 개수 | 중앙값(초) | 90% 분위(초) |
|---|---|---|---|
| 4.5~5.5km 세션의 모든 연속 점 쌍(풀링) | 4,126,579 | 4 | 7 |
| 5.000km를 가로지르는 구간(병합되지 않은 5.0km 이상 세션) | 5,406 | 5 | 8 |

5.000km 도달 지점이 스킵된(점프·시간 역전) 구간 안인 세션: 0건(위 5,406건 중). 선형 보간은 점 사이 속도가 일정하다고 가정하므로 간격이 길수록 도달 시각의 불확실성이 커진다. 간격 분위는 점 쌍 풀링 값이며 세션별 분포는 계산하지 않았다.

### A-4. 병합 세션

| 항목 | 값 |
|---|---|
| 전체 병합 세션(merged_count>1) | 4,072 |
| 그중 4.5~5.5km 세션 | 241 |
| └ 5.0km 이상 | 115 |
|   └ 5.000km 지점이 첫 조각 안(조각 사이 공백이 5km 시간에 들어가지 않음) | 1 |
|   └ 5.000km 지점이 두 번째 이후 조각 안(조각 사이 공백이 경과 시간에 포함됨) | 114 |

병합 세션의 `actual_distance_km`는 조각 거리의 합이며 조각 사이 거리는 더하지 않는다(`08_session_merge.py`, 합산 확인: 전 병합 세션에서 조각 합과 일치). `duration_sec`은 마지막 조각 종료 − 첫 조각 시작이라 조각 사이 공백이 들어간다. 따라서 처리는 **가능**하다: 조각을 시작 시각 순으로 이어 조각 거리 합이 5.000km에 도달하는 조각 안에서 보간하고, 경과 시간은 그 시각 − 첫 조각 시작으로 정의하면 공백이 경과 시간에 자동 포함된다(이 값 자체는 계산하지 않았다). 단 5.000km 지점이 두 번째 이후 조각에 있으면 5km 시간에 조각 사이 공백이 섞이므로, 병합 세션을 5km 기록에 쓸지는 [결정 필요]이며 병합 세션 제외는 민감도로 볼 수 있다.

## C. 5km 쌍의 정의와 "관측된 러닝 기록의 공백"

쌍 정의 확인: 쌍은 "같은 사용자의 연속된 두 5km 세션 사이에 다른 달리기 세션(길이 무관)이 하나도 없는 경우"다. 구현은 사용자의 **모든 달리기 세션을 시작 시각순으로 정렬**했을 때 두 5km 세션이 바로 이웃인지로 판정한다(`35_data_audit_5km.py:rest_pairs`와 같은 규칙, 이 스크립트에서 재구현). 따라서 공백 = 모든 달리기 기록 사이의 공백이 맞다. 공백 = (둘째 시작 − 첫째 종료) / 86,400초. 이 값은 **관측된 러닝 기록의 공백**이며 휴식 기간으로 해석하지 않는다(데이터에 없는 기록, 다른 운동, 기기 미착용 등을 구분할 수 없다).

겹침 열 정의: "둘째 5km가 정답 세션인 쌍" = 그 쌍의 둘째 세션이 B-1 최종 평가 대상 기준 시점 중 하나의 정답 세션(다음 7일의 첫 5km)인 쌍. "(직전 기록, 정답)과 일치" = 한 기준 시점의 기준 기록(직전 28일 가장 최근 5km)이 첫째, 정답이 둘째인 쌍. 한 평가 대상 기준 시점의 기준 기록과 정답 사이에는 입력 4회 이상 조건 때문에 다른 달리기 기록이 있을 수 있어, 이 경우 그 둘은 "사이에 다른 기록 없음" 쌍이 아니다.
