# 10월 3주차 2·3번 사전 선언 (실행 전 작성, 결과 확인 후 변경하지 않음)

이 문서는 `31_same_scope_comparison.py`를 **실행하기 전에** 작성했다. 아래 후보·지표·비교쌍·선택 규칙·중단 조건은 결과를 본 뒤 바꾸지 않는다. 새 모델 종류는 추가하지 않는다(기존 Ridge/GBM/MLP의 입력 피처 변형만). 모델 선택은 기존과 같은 CV(`ridge_lib` GroupKFold, 시드 42)와 내부 검증으로만 하고 **테스트 점수로 고르지 않는다**.

## 1. 평가 조건과 cold-start 정의
- cold-start: 사용자 단위 80/20 분할(03단계 배정 재사용). **학습에 없던 사용자이지만 타깃 이전 기록이 5회 이상 있는 조건**이다(전체 이력 중앙값 피처는 5회보다 더 먼 과거까지 사용). 기록이 전혀 없는 신규 사용자는 평가에 없다.
- personalized: 사용자별 시간순 history/hold-out(06단계와 동일 80/20).
- 평가 윈도우는 7~9단계와 같은 24단계 확장 피처 윈도우(cold-start test 149명/21,977, personalized hold-out 742명/20,628).

## 2. 비교 그룹 (그룹 안에서만 순위·유의성 보고, **그룹을 가로지르는 순위는 매기지 않는다**)
**그룹 (a) 최근 5회만 쓰는 방법**: median-5, Ridge15, GBM15, MLP15.
**그룹 (b) 타깃 이전 전체 이력을 쓰는 방법**: 전체 이력 중앙값, (d) 0.5×median-5+0.5×전체 이력 중앙값(탐색적 baseline), Ridge22, GBM22, MLP22.
- (d)는 0.5/0.5 튜닝 없는 고정 상수이나 9단계 결과를 본 뒤 추가한 탐색적 baseline이다.
- (b)의 median-5는 비교 참고용으로 표에 함께 두되 그룹 (a)의 구성원이며 (b)의 순위에는 넣지 않는다. 그룹 (b)의 기준(reference)은 전체 이력 중앙값이다.

## 3. 후보 정의와 선택 규칙 (신규 학습이 필요한 것: Ridge15, GBM15, MLP15)
- **입력**: 15피처 = 과거 5세션 × (실제 거리, 평균 페이스, 평균 심박) (`X[:, :15]`). 22피처 = 15 + 7개 요약 피처(전체 이력 중앙값·누적 세션 수 포함).
- **Ridge15**: `ridge_lib.RidgePipeline`, alpha는 기존 격자 `RIDGE_ALPHA_GRID`(10개)에서 cold-start는 train 사용자 GroupKFold(5-fold, 시드 42) 평균 CV MAE, personalized는 시간순 inner-split 검증 MAE가 최소인 값. (기존 종합표 6a는 22피처용 alpha=1e4를 15피처에 썼다 — 참고용 "레거시 6a"로 별도 표시하고 값은 바꾸지 않는다.)
- **GBM15**: `gbt_lib` 직접 구현, 기존 격자 `HGB_PARAM_GRID` 8개(learning_rate∈{0.03,0.1}, max_iter∈{100,300}, max_depth∈{2,3}), min_samples_leaf=20, n_bins=32 고정. 두 형태(absolute_error 직접 예측 / median5+잔차)별로 격자를 CV(cold-start GroupKFold 5-fold 평균 MAE, personalized 시간순 inner-split MAE)로 선택하고, 두 형태 중 CV MAE가 더 낮은 쪽을 주결과로 쓴다(7단계와 동일 규칙).
- **MLP15**: 기존 27번 코드(`select_mlp_hparams`, `train_mlp_fixed_epochs`) 재사용, 격자 8개(은닉층 {1,2}×폭 {32,64}×weight decay {0,1e-4}), 두 형태(직접/median5+잔차)별로 검증 MAE(cold-start는 ridge_lib GroupKFold 첫 fold, personalized는 시간순 inner-split)로 선택, 두 형태 중 검증 MAE가 낮은 쪽이 주결과. 선택 시드 42, 최종 재학습은 전체 학습 자료에서 선택된 에폭 수로 고정, 대표 시드 42의 예측으로 평가표를 만들고 5개 시드(1,2,3,42,999) 평균±표준편차를 참고로 병기.
- **그룹 (b)의 기존 방법(Ridge22 alpha=1e4, GBM22, MLP22, 전체 이력 중앙값, (d))**: 재탐색하지 않고 기존 선택을 그대로 쓴다(GBM22 하이퍼파라미터는 `28_model_comparison.py` 상수, MLP22는 `docs/mlp_selected_hyperparams.json`).
- **중단 조건**: 그룹 (b) 방법과 레거시 6a의 MAE/RMSE가 `docs/model_comparison.md`의 값과 소수 셋째 자리에서 다르면 즉시 중단하고 보고한다.

## 4. 지표와 통계 (모든 방법 공통)
- **풀링 MAE(윈도우 평균)**, **풀링 RMSE**, **macro MAE(사용자별 MAE의 평균, 사용자 1명 = 1표)**. macro RMSE는 계산하지 않는다.
- **신뢰구간**: 사용자 단위 cluster bootstrap — 평가 사용자를 복원추출(사용자 수만큼, 2000회, seed 42), 뽑힌 사용자의 **모든 윈도우**를 함께 사용, 모든 방법에 같은 추출을 적용한 쌍체 비교, 95% percentile CI. macro MAE는 뽑힌 사용자(중복 포함)의 사용자별 MAE를 중복 횟수 가중으로 평균한다.
- **비교쌍(결과 확인 후 변경 없음)**: 그룹 안의 **모든 쌍**(a: 6쌍, b: 10쌍)에 대해 풀링 MAE, macro MAE, 풀링 RMSE 차이(앞−뒤, 양수면 뒤가 더 낮음)와 CI. 다중 비교 보정은 하지 않는다(탐색적 쌍 비교 다수 → 개별 CI를 확정 근거로 쓰지 않음).
- **개선폭 표기(분모 구분)**: 그룹 기준 방법(a: median-5, b: 전체 이력 중앙값) 대비 (1) 절대 개선(초/km), (2) 'reference MAE 대비 %', (3) '평가 윈도우 타깃 페이스 중앙값 대비 %'를 각각 구분해 쓴다.
- **유의하지 않은 비교**에는 "CI가 0을 포함 — 동등성(차이가 없음)의 입증이 아님"이라고 쓴다.
- **사용 데이터 수**: 각 표에 평가 사용자 수·윈도우 수·재표집 방법을 본문에 명시한다.

## 8. 3주차 4번 사전 선언 — 코칭 판정 보류 실험 (실행 전 작성, 결과 확인 후 변경하지 않음)
**모든 목표는 합성 시나리오이며 실제 사용자 목표 기반 코칭 성능이 아니다.** 새 예측 모델은 추가하지 않는다(기존 median-5, (d), GBM22, MLP22의 하이퍼파라미터·학습 방식을 그대로 사용). 스크립트는 `32_coaching_abstain.py`(numpy/ridge_lib/gbt_lib/torch만, sklearn 의존 금지). 29번의 `%TEMP%` 예측 캐시는 쓰지 않고 예측을 새로 계산한다.

### 8-1. 범주별 건수·혼동행렬 (docs/coaching_definition.md 정의 기준)
- 예측기: median-5, 전체 이력 중앙값, 상수 규칙(학습/이력 구간 최빈 범주), GBM22, MLP22.
- 행 = 실제 6번째 세션 페이스로 판정한 범주, 열 = 예측 페이스로 판정한 범주. 건수와 행 정규화 %를 함께 표시. 실제 범주의 분포와 다수 범주 비율을 표시.
- **주 조건 δ=5%·데드라인 8주**를 cold-start/personalized별로 본문에 혼동행렬로, 나머지 5개 조건(δ 3/5/10% × 8/4주 중 주 조건 제외)은 건수 표만.

### 8-2. 판정 보류 실험 설계
- **대상 예측기**: median-5, (d) 0.5×median-5+0.5×전체 이력 중앙값, GBM22, MLP22. **구간 수준은 80%와 90% 두 가지만.**
- **구간**: 예측 ± q, q = 보정 자료의 절대 잔차 |y − 예측|의 해당 수준 분위수(`np.quantile`, 선형 보간). (예측기, 평가 조건, 수준)마다 하나의 전역 상수 q — 구간 폭은 윈도우와 무관하게 2q로 일정하다.
- **보정 자료는 테스트와 분리되고, 잔차는 모델 적합에 쓰이지 않은(out-of-sample) 값**이어야 한다:
  - **cold-start**: train 사용자 전체에 대해 ridge_lib GroupKFold(5-fold, 시드 42)의 OOF 예측 잔차. 모델(GBM22, MLP22)은 fold마다 해당 fold를 제외한 train 사용자로 기존 하이퍼파라미터·에폭(고정)으로 새로 학습하고 제외된 fold 사용자의 윈도우를 예측. median-5와 (d)는 적합이 없는 규칙이라 같은 train 윈도우의 잔차를 그대로 사용.
  - **personalized — 설계 검토 결과(제안)**: 요구 조건 (a) 보정 자료가 테스트와 분리, (b) 보정 잔차가 모델 적합에 쓰이지 않은 값, (c) 시간 순서 보존을 모두 만족하는 설계가 **가능하다**고 판단한다. 제안: 기존 모델 선택에 쓰는 시간순 inner-split(`personalized_inner_split`: 사용자별 history 윈도우를 시간순으로 앞 80%/뒤 20%)을 그대로 쓴다. 모델을 history 앞 80%(inner-train)로 새로 학습하고, 뒤 20%(inner-val)의 잔차를 보정 자료로 쓴다. (a) inner-val은 history 안이라 hold-out(테스트)과 분리, (b) inner-val은 그 모델의 학습에서 제외, (c) 각 사용자 안에서 inner-train < inner-val < hold-out의 시간순 유지. 한계(미리 기록): 보정용 모델은 history의 80%만 본 모델이고 최종 평가 모델은 history 전체로 학습한 모델이라 잔차 분포가 약간 다를 수 있으며, 보정 구간이 hold-out보다 이른 시점이라 시간에 따른 분포 변화를 반영하지 못한다. median-5와 (d)는 적합이 없는 규칙이라 같은 inner-val 윈도우의 잔차를 사용. 이 제안은 결과를 보기 전에 고정하며, 실행해 결과가 나온 뒤에 사용자 확인을 받는다.
- **판정 규칙**: 구간의 하한(예측−q)과 상한(예측+q)을 각각 현재 능력(median-5)·체크포인트 기준으로 같은 방식(`coaching_lib` 규칙과 동일한 벡터화)으로 판정 범주로 변환해, 두 범주가 같으면 그 범주로 판정하고 다르면 '판정 보류'.
- **조건**: 주 조건 δ5%·8주 + 나머지 5개 조건은 보류율·판정 사례 불일치율만 요약표로. 분모는 데드라인 이내 윈도우.
- **보고 지표**: (1) 보류율, (2) 판정한 사례의 불일치율(사용자 단위 cluster bootstrap 2000회, seed 42, 판정한 윈도우 수 합 분모의 비율 추정, 95% CI), (3) 강제 판정(보류 없음) 불일치율과의 차이(판정 사례 − 강제, 같은 재표집 쌍체 CI), (4) 테스트에서의 구간 포함률(|y−예측| ≤ q인 윈도우 비율)과 평균 구간 폭(2q), (5) **통제 비교**: 같은 개수만큼 윈도우를 무작위로 보류했을 때 나머지 윈도우의 불일치율(1000회 반복, seed 42, 평균과 2.5/97.5 범위; 윈도우 단위 무작위, 사용자 구조 무시).
- **해석 규칙**: 보류율이 매우 높게 나와도 결과 그대로 보고하며, 해석은 '관찰'로만 쓴다. 불일치율은 고정 규칙에 대한 판정 일치도이며 코칭 효과·목표 달성의 검증이 아니다. 경과 시간 기준 페이스가 느린 세션을 체력 저하·목표 실패로 해석하지 않는다.
- **중단 조건**: 이 스크립트가 재현한 강제 판정 불일치율과 CI(전 조건 × 5개 예측기 + 상수 규칙)가 기존 `docs/coaching_results.md` 3-2절 값과 표시 자릿수에서 다르면 즉시 중단하고 보고한다.

8-2의 판정 보류 실험 결과(보류율이 96~100%, 판정된 윈도우가 대부분 '앞서감' 등 예측값에 따라 선택된 부분집합)를 본 **뒤에** 추가한 분석이며, 사전 선언된 비교가 아니다. 해석은 '관찰'로만 쓴다.
- **통제**: 각 (예측기, 평가 조건, 수준)에서 **판정된(보류되지 않은) 윈도우 부분집합**에 대해 같은 윈도우의 (i) 상수 규칙(항상 학습/이력 구간 최빈 범주) 판정 불일치율과 (ii) median-5 판정 불일치율을 계산해 그 예측기의 판정 사례 불일치율 옆에 표시한다. CI는 사용자 단위 cluster bootstrap(2000회, seed 42, 판정 윈도우 수 합 분모의 비율). 보조로 (예측기 판정 불일치율 − 상수 규칙 불일치율)의 같은 재표집 쌍체 CI를 함께 표시한다.
- **q 표기**: q80·q90은 초/km 단위로 소수 셋째 자리까지 표기하고, 실제 계산한 상·하한의 폭이 2q와 일치하는지 코드로 검증한다.
- **요약 문구**: 문서 요약에 '보류율이 96~99%이며 이 설계의 구간 폭은 범주 폭보다 훨씬 넓어 판정 보류가 거의 전부이고, 보류가 코칭 품질 향상을 뜻하지 않는다'를 명시한다.

## 9. 3주차 5번 사전 선언 — 극단 세션 ↔ 윈도우 대응 (분류 규칙·임계값 고정, 결과를 보기 전에 작성하며 이후 바꾸지 않음)
새 예측 모델·새 코칭 실험은 없다. 스크립트는 `33_extreme_session_map.py`(numpy/pandas/ridge_lib/gbt_lib/torch만, sklearn 의존 금지). 어떤 문서에도 사용자 ID·세션 ID·개인 경로를 쓰지 않는다(세션 단위 대응표 원본은 `data/` 아래에만 저장, git 제외).

### 9-1. 극단 세션
기존 정의 그대로: **경과 시간 기준 평균 페이스 > 1000초/km**(`config.EXTREME_PACE_THRESHOLD_SEC_PER_KM`), 정제 세션 표(`run_sessions_deduped_merged`) 기준 **826건(0.781%)**이어야 한다(`docs/target_pace_definition.md`). 다르면 중단하고 보고한다.

### 9-2. 극단 세션의 분류 규칙 (세션 표에 있는 열로 가능한 것만, 임계값 고정)
| 코드 | 규칙 | 사용 열 |
|---|---|---|
| (a) 병합 유래 | `merged_count > 1` | 세션 표 `merged_count` |
| (b) 휴식 포함 의심 | 정지 비율 `gap_ratio >= 0.5` (정지 비율 = 1 − 이동시간/경과시간, 18단계 산출) | `run_sessions_deduped_merged_with_moving`의 `gap_ratio` |
| (c) 짧은 거리 | `actual_distance_km < 1` | 세션 표 `actual_distance_km` |
| (d) 미분류 | 위 (a)~(c)에 모두 해당 없음 | — |
- **한 세션이 여러 범주에 해당하면 중복 집계**하고 그 사실을 표기한다((a)~(c) 합이 세션 수보다 클 수 있음; (d)는 (a)~(c) 어디에도 해당하지 않을 때만).
- **GPS 오류·중복 흔적**은 세션 표만으로 판정할 수 없다(포인트 단위 정보는 01단계에서 이미 필터링되었고 중복은 16단계에서 제거된 세션만 남아 있음). 따라서 **'미판정'**으로 두고 이유를 적는다. 원본 재파싱은 하지 않는다. (d) '미분류'는 'GPS 오류나 중복이 아님'을 뜻하지 않는다.

### 9-3. 세션 ↔ 윈도우 대응 (5-1)
- 극단 세션마다: 타깃으로 등장하는 윈도우 수, 입력으로 등장하는 윈도우 수(윈도우당 입력 5세션이므로 한 세션은 최대 5개 윈도우의 입력), cold-start 평가 집합(test)·personalized 평가 집합(hold-out) 포함 여부. 문서에는 건수 요약만, 세션 단위 표는 `data/` 아래에 저장.

### 9-4. 윈도우 단위 분석 (5-2, 5-3)
- 대상 예측기: median-5, GBM22, MLP22(기존 하이퍼파라미터, 재탐색 없음). 평가 조건 두 가지(cold-start test, personalized hold-out).
- 제곱오차 상위 1% 윈도우 = 제곱오차 내림차순 상위 `ceil(0.01 × n)`개. 각 상위 1% 윈도우를 (i) 타깃이 극단 세션, (ii) 타깃은 아니지만 입력 5세션 중 극단 세션 포함, (iii) 둘 다 아님으로 분류해 비율을 보고. 상위 1%가 전체 제곱오차(SSE)에서 차지하는 비중(기존 문서의 92~93%와 일치 확인), 타깃이 극단인 윈도우 전체가 SSE에서 차지하는 비중도 보고.
- 상위 1% 윈도우의 **타깃 세션**에 9-2 분류 규칙을 적용한 (a)~(d) 분포(중복 집계 표기)와, 극단 세션 전체의 (a)~(d) 분포.

### 9-5. 민감도 (5-4, 원래 평가 집합 결과는 유지)
- 민감도 (i): **타깃이 극단인 윈도우만 제외**. 민감도 (ii): **타깃 또는 입력에 극단 세션이 포함된 윈도우를 모두 제외**(= `docs/baseline_results.md` C-1절의 기존 민감도와 같은 제외 기준; 해당 표의 median-5 행은 04/06단계 윈도우 기준이므로 같은 코드를 04/06 윈도우에 적용해 먼저 정확히 재현하고, 24단계 윈도우 결과는 윈도우 수 차이로 소수점 이하가 약간 다를 수 있음을 표기한다).
- 방법: median-5, GBM22, MLP22(+ 참고로 전체 이력 중앙값, (d))의 MAE·RMSE와 **median-5 대비 차이**(앞서 3주차 문구 기준: 양수 = 모델이 더 낮은 오차) 및 95% CI(사용자 단위 cluster bootstrap 2000회, seed 42).
- 해석은 '관찰'로만 쓴다. 세션 비율(0.781%)과 윈도우 단위 기여(상위 1% 윈도우의 SSE 비중 92~93%)는 집계 단위가 다르므로 문서 첫머리에 명시한다. 극단 페이스가 GPS 오류인지 실제 휴식 포함인지는 검증하지 않았다(미확인).

## 10. 3주차 7번 사전 선언 — 다중 세션 집계 코칭 평가 설계안 (설계 문서 + 가용성 점검까지만; 모델 학습·평가·구현 없음)
이 절은 `34_multisession_availability.py`(표본 수를 세는 기술통계)를 **실행하기 전에** 작성했고, 가용성 점검 결과를 본 뒤 설계를 바꾸지 않는다. 이 단계에서는 어떤 모델도 학습·평가하지 않고 `docs/multisession_coaching_design.md`(설계)와 그 안의 가용성 표만 만든다. 구현은 사용자 승인 후. 모든 목표는 합성 시나리오다.

### 10-1. 과제 정의와 주 과제 제안
- (A) 현재 상태 판정: 최근 k주 집계 페이스로 현재 위치를 목표 대비 판정. 정답이 없고 판정이 관측값의 결정적 함수라는 한계가 있어 **설명용 보조**로만 둔다.
- (B) 다음 주 성과 예측: 예측 시점 t 이전에 끝난 세션의 집계로 t 이후 7일의 집계 페이스를 예측. 실제 값이 정답이고 같은 단위 baseline과 비교 가능 → **주 과제(B)**로 제안한다(사용자 판단과 같음). 단, (B)의 평가 표본은 '타깃 주에 러닝이 있었던 앵커'로 조건부이므로(미래 활동에 의존한 선택) 활동 여부 자체는 예측하지 않는다는 한계를 명시한다.

### 10-2. 고정할 항목 (후보 값; 아래 값이 사전 고정이며 가용성 결과 후 바꾸지 않음)
- **앵커 시점 t**: epoch 초를 UTC로 해석한 **UTC 월요일 00:00**의 7일 격자(타임존 정보가 데이터에 없어 사용자 현지 시각으로 변환하지 않음; 현지 시각과의 어긋남은 한계로 기록, 격자 시작 요일 7가지로 표본 수가 얼마나 변하는지만 기술통계로 확인).
- **집계 기간(입력)**: 28일 — 입력 세션 = `t − 28일 ≤ end_time < t`인 세션(end_time = start_time + duration_sec). **t 시점에 끝나지 않은 세션(end_time ≥ t)은 입력에 넣지 않는다.**
- **최소 입력 세션 수 후보**: 3, 4. **타깃 주**: 시작 시각이 `[t, t+7일)`인 세션 중 최소 세션 수 후보 1, 2.
- **집계 방식**: 세션별 경과 시간 기준 평균 페이스(`avg_pace_sec_per_km`, 메인 정의)의 **중앙값**(극단값에 강건; 기존 baseline과 동일한 집계).
- **누수 규칙**: 앵커별로 `max(입력 세션 end_time) < t`, 타깃 세션 `start_time ≥ t`를 assert로 검증하고, 전체 이력 baseline은 `end_time < t`인 세션만 사용한다.
- **목표 기준**: 합성 목표 δ∈{3%,5%,10%}(현재 능력 = 입력 집계 중앙값), 데드라인 8주, 주간 체크포인트 선형 보간(`coaching_lib` 규칙 재사용). 모두 합성이며 실제 사용자 목표가 아니다.

### 10-3. baseline과 지표 (같은 단위 = 앵커의 타깃 주 집계 페이스)
- baseline: (1) 직전 28일 입력 집계 중앙값, (2) `end_time < t`인 전체 이력 중앙값, (3) 마지막 세션 페이스. 집계했다고 오차가 자동으로 줄어든다고 가정하지 않는다.
- 지표: MAE·RMSE 둘 다(풀링), macro MAE 병기. 분석 단위는 (사용자, 앵커 주). 같은 사용자의 앵커들은 28일 입력 창이 3주 겹치고 이력을 공유해 독립이 아니므로 **사용자 단위 cluster bootstrap(2000회, seed 42)**으로 CI를 낸다.

### 10-4. 가용성 점검(기술통계) 설계와 배제 규칙
- 입력: 정제 세션 데이터(`data/user_sequences.pkl`, 세션 6개 이상 적격 사용자 742명). 조합 4개: 입력 28일 × 최소 입력 세션 {3,4} × 타깃 주 최소 세션 {1,2}. 각 조합의 (사용자, 앵커) 표본 수와 사용자 수를 전체·cold-start(train/test 사용자 분할)·personalized(사용자별 앵커 시간순 앞 80% history / 뒤 20% hold-out, `int(0.8n)` 규칙)별로 센다.
- **충분성 기준(사전 고정)**: 평가 집합이 cold-start test에서 사용자 ≥ 100명 그리고 앵커 ≥ 1,000개, personalized hold-out에서 사용자 ≥ 300명 그리고 앵커 ≥ 1,000개를 모두 만족하는 조합만 후보로 둔다. 기준 미달 조합은 배제 근거가 된다.
- **선택 규칙(사전 고정)**: 기준을 통과한 조합 중 (최소 입력 세션 수, 최소 타깃 세션 수)가 사전식으로 가장 큰 조합을 주 설정으로 제안한다(집계가 더 많은 세션에 근거하도록). 통과 조합이 없으면 설계를 확정하지 않고 보고한다.
- 타깃 주에 러닝이 없는 앵커 비율(입력 조건은 만족)도 기술통계로 함께 기록해 조건부 평가의 선택 편향 크기를 가늠한다.
